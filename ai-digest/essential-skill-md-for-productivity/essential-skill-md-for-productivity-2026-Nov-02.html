1. Backslash urges inventories and allowlists for agent Skills on developer laptops

Backslash Security published guidance on governing AI coding agents on developer workstations, dated 1 November, and singled out Skills as a distinct risk. Because a Skill bundles reusable instructions with executable scripts, a malicious or poorly configured one can tell an agent to run commands or send out sensitive data. The post recommends keeping an inventory of installed Skills, assessing each component before approval, flagging excessive permissions and unsafe instructions, and enforcing central allowlist or block policies. It also stresses continuous reassessment, since editing a Skill after approval changes what the agent can do. For anyone collecting productivity skills, the practical takeaway is to treat every SKILL.md folder as code that needs review.

Sources: Backslash Security

2. Copilot CLI 1.0.106 keeps /skills add, remove and reload in sync with the session

GitHub's Copilot CLI shipped 1.0.106-2 on 1 November with a skills fix: changes made through /skills add, remove and reload now stay in sync with the skills the live session actually holds, and refresh failures are reported immediately instead of silently. That closes a gap where a freshly installed or removed skill could look active in the menu but not match what the agent could invoke. It follows a run of Copilot CLI releases tightening skill handling, and it matters most for people who add skills mid-session. The preceding build, 1.0.106-1, carried no skill changes.

Sources: github/copilot-cli releases

3. Claude Code 2.1.314 caps skill and plugin trash folders and retries gateway-rejected requests

Claude Code 2.1.314, released on 30 October, caps ~/.claude/skills/.trash and ~/.claude/plugins/.trash at roughly 1,024 entries each, whatever cleanupPeriodDays is set to, after both folders were found to grow without limit. The same release fixes the skill file watcher re-checking every removed skill kept in the trash, which added file-system load that grew with each removal. A separate fix resends a request once without tool search when a gateway rejects its tool_reference blocks, and remembers that for the session. Together they are housekeeping that benefits anyone who installs and prunes many skills. The next release, 2.1.316, was covered yesterday for its sub-agent effort setting.

Sources: anthropics/claude-code releases

4. US Department of Energy releases “Genesis Agent Skills” for the Genesis Mission

From earlier this month (16 October, so outside the 24-hour window): the US Department of Energy released Genesis Agent Skills, described as the first set of technical resources from its ModCon programme on Transformational AI Models and Data and the American Science Cloud. The package was developed by the Baseline AI R&D Capabilities team, with contributions from Princeton Plasma Physics Laboratory, PNNL and Lawrence Berkeley National Laboratory among others. The PPPL announcement does not state how many skills are included or confirm the SKILL.md format, so treat the packaging details as unverified. It is a notable sign of national labs publishing skills as shared research infrastructure.

Sources: Princeton Plasma Physics Laboratory

5. oh-my-claudecode ships v5.7.26 to v5.7.29 in a day, with skill paths needing the omc CLI

The open-source oh-my-claudecode orchestration layer for Claude Code published four releases on 1 November, v5.7.26 through v5.7.29, the last landing in the evening. The release notes remind users that CLI-dependent skill paths such as ask and the CLI-backed team workflow require the omc CLI from the npm package, so updating the plugin alone is not enough. Earlier releases in the same line routed factory CI failures to the bundled debug skill and added mission-board sessions. The notes give little detail beyond that, so this is mainly a signal of how quickly skill-bundle plugins are iterating.

Sources: oh-my-claudecode releases
