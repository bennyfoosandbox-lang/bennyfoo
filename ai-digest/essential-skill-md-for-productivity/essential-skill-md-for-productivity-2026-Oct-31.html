1. Claude Code 2.1.312 finds per-directory skills after you cd

Claude Code 2.1.312 fixes a bug where skills defined per directory, or scoped with a paths: list in their frontmatter, were not found once a Bash command had moved into a deeper folder of a git repository. Anyone who keeps task-specific SKILL.md files next to the code they apply to, such as a release skill in one package and a migration skill in another, could see those skills silently fail to load partway through a session. The same release fixes a command with an invalid name blocking all other commands from loading, which could leave claude -p with no output, and it stops Claude from overwriting very large CLAUDE.md or rules files after reading only their start. It is a small changelog entry, but it affects how reliable repo-local skills are in long sessions. The release is from 27 October, so it is a few days older than the usual window.

Sources: Releasebot: Claude Code release notes

2. Codex 0.166.0 starts attributing traces to skills

OpenAI's Codex 0.166.0, released on 29 October, adds turn, tool and skill attribution to its traces, records skill and plugin catalog sizes when they are published, and clarifies the skill on/off summaries in the terminal UI. Together these let a team see which skill a given tool call came from and how big the catalog the agent is choosing from has become, which is the first thing you need when deciding which skills are worth keeping. The headline features of the release are elsewhere (keyboard transcript search, GPT-6.1 Terra model support, codex queue --resume, and codex doctor --network-only), so the skill changes are easy to miss in the notes. It follows the 0.164 and 0.165 releases covered earlier this week, which reworked how skills are refreshed and read.

Sources: Releasebot: Codex release notes, GitHub: openai/codex releases

3. Genkit Go 1.14 loads Agent Skills from any filesystem

Google's Genkit Go 1.14, published on 20 October, includes a Skills middleware that loads skills following the Agent Skills specification from any Go fs.FS. That means an app can embed its SKILL.md folders in the binary, or read them from a zip or a remote store, and the model gets the instructions plus the bundled files without any extra infrastructure. The release is mostly about other things, including typed human-in-the-loop tool approval, token and cost budgets, context compression and OpenTelemetry GenAI tracing, so the skills line is one bullet under 'Also in this release'. A July Google Developers post explains the mechanism: only the frontmatter goes into the system prompt, and the full body loads through a use_skill tool when a request matches the description. This item is older than a day, but it is new to this knowledge base and shows skills spreading from coding agents into application frameworks.

Sources: Genkit: Go 1.14 release post, Google Developers Blog: Agent Skills in Genkit Go

4. A 103-skill library with a productivity-and-workflow section

The seb1n/awesome-ai-agent-skills repository packages 103 complete SKILL.md workflows, not links to other repositories, for Claude Code, Codex, Gemini CLI, Cursor, GitHub Copilot, Windsurf and other tools that read the Agent Skills format. Its productivity-and-workflow folder holds file-organization, meeting-scheduler, note-taking, project-management and task-automation skills, which are the closest match to this digest's topic. It is MIT licensed, shows about 233 stars, and installs with npx skills add seb1n/awesome-ai-agent-skills, with --skill to pick a single one. The repository's last update is dated August 2026, so this is not breaking news. It is included because no earlier digest covered it and it is a compact set of productivity skills that a user can read and adapt.

Sources: GitHub: seb1n/awesome-ai-agent-skills

5. Infisical Agent Vault installs skills through access bundles

Infisical's Agent Vault documentation describes a way to manage skills centrally. An admin adds a skill, a folder with a SKILL.md, to an access bundle, and infisical agent-vault run then installs it for each agent started under that bundle, including Claude Code and Codex. Documented limits are 250 skills per organization, 50 files per skill, 256 KB per file and 1 MB in total, with names of up to 64 characters and descriptions of up to 1,024. The docs also warn against putting API keys in a skill, because anyone with a session token can download it and the CLI saves skills as plain files on the agent's host; credentials should be attached as services instead. Agents that use the proxy without agent-vault run, such as the Hermes and OpenClaw gateways, do not receive skills. The page is undated, so treat it as current documentation rather than a dated announcement.

Sources: Infisical docs: Agent Vault skills
