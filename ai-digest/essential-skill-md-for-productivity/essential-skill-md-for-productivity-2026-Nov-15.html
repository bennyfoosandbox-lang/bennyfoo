1. Anthropic tightens its Word, PowerPoint, Excel and PDF skills so agents produce files Office won't reject

Anthropic merged a large update to the four document skills in its public anthropics/skills repository on 14 November (PR #2217, 36 files, +3,273/−622 lines). The docx, pptx and xlsx skills get stricter validation and more accurate tracked-changes checks. The PowerPoint checker now catches charts that PowerPoint would refuse or quietly "repair", such as duplicate series order, invalid dash styles and non-numeric axis settings, plus animations that point at shapes no longer on the slide. The pptx skill adds slide_text.py and apply_theme.js with expanded deck guidance, and xlsx's recalc.py now writes back only computed values. The docx SKILL.md also adds a rule that every heading level used must have its own style, and packaging that strips ZIP folder entries. If you rely on these skills for reports and decks, pull the update: fewer generated files will open with a repair prompt.

Sources: anthropics/skills PR #2217, Merge commit 1780c5e, anthropics/skills commit history

2. Codex 0.168 makes repository skills obey the session's file permissions

OpenAI's Codex 0.168.0 (13 November, about 48 hours before this run) changes how skills from a repository are found and read. Four changes (#59278, #59279, #59280, #59291) make skill discovery and loading respect the filesystem permissions in force for the current turn, including for skills discovered by an executor. A skill in a folder the session isn't allowed to read is no longer loaded just because it sits in the repository. The release also adds outcome metrics for skill reads and installation listings (#59295), and lets a model catalog override the guidance plugins give the model (#58894). It also packages an agent "message board" MCP connection as a plugin (#58908). Together these make sandbox settings a real boundary for skills, which matters when you open repositories you didn't write.

Sources: Codex 0.168.0 release (GitHub), Codex PR #59280: respect filesystem permissions in skill discovery, Codex PR #58894: model catalog overrides for plugin guidance

3. OpenClaw 2026.11.5 betas fix a skills import race and keep ClawHub installs that time out

OpenClaw published two pre-releases of its 2026.11.5 line: beta.2 on 12 November and beta.3 on 15 November. Beta.2 fixes a race in which workspace memory and skills could be imported twice or in the wrong order on the first turn, when plugins load from TypeScript source. Beta.3 keeps a ClawHub install or update the registry had already accepted when the client times out, instead of dropping it and leaving a skill half-installed. It also preserves external plugins' data during update rehearsals, and keeps cron and system replies from using plugin scopes that have closed. These are reliability fixes rather than new features. They matter if you run OpenClaw unattended with skills from ClawHub, where a silently missing skill is hard to notice.

Sources: OpenClaw v2026.11.5-beta.3 (GitHub), OpenClaw v2026.11.5-beta.2 (GitHub), OpenClaw releases

4. Google previews Gemini for healthcare, built on skills that follow a hospital's own procedures

This item is older than the 24-hour window. Google Cloud opened a U.S. preview of Gemini for healthcare on 10 November for providers and payers on Gemini Enterprise Standard and Plus. It extends the general Gemini agent rather than shipping as a separate app, and its main building block is skills. These are multi-step instructions written by healthcare experts for tasks such as medical-record synthesis, pre-appointment preparation, coverage and policy review, and payer benefit determination. Organizations can write their own skills to follow their standard operating procedures. Connectors include Epic and Oracle Health EHRs (read-only for now, per one report) and an InterSystems FHIR MCP server. It is another large vendor packaging industry workflows as reusable skills plus connectors, as Anthropic did for manufacturing this week.

Sources: Google Cloud Press Corner: Gemini for healthcare, Unite.AI, Tech-ish, iThome (Chinese)

5. Gemini CLI 0.68 checks extensions before you install or publish them

This item is older than the 24-hour window. Gemini CLI 0.68.0 (10 November) extends gemini extensions validate <path>, which checks a local extension before you install or publish it (PR #29980). It checks the gemini-extension.json manifest: context files must exist and sit in safe locations, versions must be valid semver, and MCP server configuration must be valid. The PR also adds evaluation tests. The release serializes concurrent installs of the same extension with a per-extension lock (#30039) and handles stream failures during extension downloads (#30100). Gemini CLI extensions can bundle skills, so this gives authors one command to catch a broken package before users find it.

Sources: Gemini CLI v0.68.0 release (GitHub), Gemini CLI PR #29980: extension validation, Changelog for v0.68.0 (PR #30224), Gemini CLI docs: Creating Agent Skills
