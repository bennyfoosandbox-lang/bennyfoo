1. Claude Code 2.1.326 lets skills with shell preambles load in Code Mode, and stops refusing plugins over a bad display field

Claude Code 2.1.326, released 16 Nov, fixes skills and slash commands that failed to load in Code Mode under auto mode when they contained an inline ! command needing approval: Claude is now asked to run that command instead. It also fixes background subagents in Code Mode that preload such a skill. Plugin loading changes too. Enabled plugins that used to be refused because a display field in plugin.json (such as author or homepage) was malformed now load with their hooks and MCP servers, and /plugin and claude plugin list note the ignored field. Anthropic tells administrators to check the plugins they deploy. Smaller skill fixes: a skill, command or agent created during a session is found right away, pressing Ctrl+C twice in /skills now saves and closes the panel instead of quitting, and the / menu no longer repeats rows when two skills share a name. The built-in /claude-api skill now builds agents on Managed Agents by default.

Sources: Claude Code v2.1.326 release, Claude Code changelog

2. Google's skills library adds a Release Radar for Cloud release notes and a batch of GKE and Compute Engine troubleshooters

Google's official google/skills repository merged a large batch on 16 Nov. The main addition is google-cloud-release-radar: a 278-line SKILL.md with a dependency-free Python CLI and a catalogue of 368 products and four bundles (AI, Data, App Mod and Security). It keeps a personal watchlist and checks feeds over a set window or since the last check. It filters by FEATURE, DEPRECATION, BREAKING, SECURITY and other types, and it posts to a Google Chat webhook only after the user confirms. By default it reads public release-note feeds and needs no Cloud project; an optional BigQuery mode dry-runs each billable query first. The same day brought troubleshooting skills for GKE and Compute Engine. gke-capacity-triage (about 880 lines) works out whether Pending pods are blocked by capacity, quota or configuration and drafts a ComputeClass change for review. Others check StatefulSets that are unprotected or lack probes, and cover host events and MIG autoscaling. Ads API, IAM, monitoring and Agent Platform skills were refreshed too. Release Radar is a good model for a "what changed this week" skill: a narrow trigger, a script that does the fetching, and a confirmation before anything is sent.

Sources: google-cloud-release-radar commit, gke-capacity-triage commit, google/skills commit history

3. The skills CLI 1.9 pins every lock entry to its installed commit and adds --rename

Vercel Labs' skills CLI (npx skills) shipped v1.9.0 on 16 Nov, a week after 1.8 introduced lock v2. Each lock entry is now pinned to the exact commit that was installed (#2735). Lockfile updates are serialized and written atomically (#2750), so parallel installs or a crash can't leave a half-written skills-lock.json. A new --rename option installs a skill under a different name (#2722), which helps when two sources ship skills with the same name. Skill links also stay valid when an agent's skills directory is itself a symlink (#2283). The CLI now warns when a GitHub rate limit makes it clone a repository instead of using its faster blob download (#2761). Together these changes make a committed lockfile a more dependable way to give a whole team the same skill versions.

Sources: skills v1.9.0 release, PR #2735 (commit-pinned locks), PR #2750 (atomic lockfile)

4. Anthropic follows up its Office skills update: safer unpacking, and conversions that drop links to outside files

Two days after the large Office-skills update in PR #2217, Anthropic merged a follow-up, PR #2221, on 16 Nov. The docx and pptx editing steps now unpack documents with Python's zipfile module and re-zip with zip -y, which stores symbolic links as links instead of copying the files they point to. validate.py now stops with a clear "cannot unpack" error when the --original file can't be read. soffice.py now removes links to files outside the document before converting a .docx, .pptx or .xlsx to PDF or an image. That last change matters most for agents that render documents from other people, where an external link could otherwise pull outside content into the output. This is a material update to Office skills already covered, so it is included.

Sources: anthropics/skills PR #2221, anthropics/skills commit history

5. Addy Osmani's agent-skills 0.6.16 makes code review check its findings and stops the frontend skill installing tools

Addy Osmani's agent-skills, a collection of engineering-workflow skills for Claude Code and other agents, released 0.6.16 on 14 Nov. That is outside the 24-hour window, so it comes from the 72-hour fallback. The code-review skill now checks each finding against callers, guards and tests, labels defects that already existed in the base, and accepts zero findings as a valid result (#736). The frontend skill no longer installs test runners or type checkers just to verify its own work. The author reports a +0.10 gain across 11 models, with package installs falling from 24% to 4% of runs (#732). Specs now carry a version, and changes to shipped features get small delta spec files (#383). The docs skill flags documentation drift by comparing commit history (#514), and the security checklist moves to OWASP Top 10:2025. The test-driven-development, code-review and debugging skills now trigger on pasted code, with tests confirming they stay quiet for neighbouring requests.

Sources: agent-skills releases, PR #736 (verified review findings), PR #732 (frontend verification)
