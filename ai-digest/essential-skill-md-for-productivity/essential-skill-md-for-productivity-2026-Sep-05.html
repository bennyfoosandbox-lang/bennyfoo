1. Anthropic ships Claude Commerce Agents, a skills-built blueprint for shopping and merchant bots

Anthropic published anthropics/commerce-agents, an Apache-2.0 reference blueprint pairing a shopping agent and a merchant agent across four runnable verticals — retail, travel, telecom and entertainment. The shopping agent is built from five discrete skills (search-discovery, purchase-research, planning-goals, customer-care and memory-personalization), while the merchant agent packages skills for sales analytics, catalog and inventory management, pricing and promotions, and marketing drafts. Early users include Shopify, Visa, Mastercard and Accenture; the code runs locally on Python 3.11+/Node 22 with any Anthropic-compatible client and deploys unchanged on the Claude API, Bedrock, Microsoft Foundry or Vertex AI. It's the clearest evidence yet that skills have become the default unit teams reach for once an agent needs to own a whole product surface, not just one trick.

Sources: Anthropic, MarkTechPost, Digital Commerce 360

2. GitHub Copilot CLI ships four releases in four days, closing sandbox escape gaps

Copilot CLI moved through v1.0.83-0 to v1.0.83-5 between August 31 and September 4, tightening the isolation around every skill and tool a session can reach: Linux sandboxes now restrict network egress to the configured proxy, and sandboxed commands on macOS and Linux can no longer reach services running on the host machine. The same run of releases added support for listing several fallback models on a custom agent (tried in order until one is available), added the new claude-fable-5-1 model ID, and added Client ID Metadata Document support for MCP OAuth sign-in. For teams wiring skills and MCP servers into daily coding workflows, the sandboxing fixes matter more than the feature adds — a skill that can reach LAN services undermines the isolation the whole model depends on.

Sources: GitHub Copilot CLI releases, Havoptic

3. K-Dense AI open-sources a 165-skill library already used by 190,000 researchers

A new paper, Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents, documents an open library of skills spanning genomics, cheminformatics, medical imaging, study design and scientific communication — each one a versioned SKILL.md plus reference material and runnable scripts that an agent loads only when a task calls for it. The authors argue that defensible scientific analysis hinges on procedural judgment calls a model doesn't know by default — which statistical test a field accepts, which identifier namespace is authoritative — and package that judgment as reusable skills instead of hoping the model infers it. The library, published on GitHub, is already used by more than 190,000 scientists, making it one of the largest domain-specific skill collections released to date and a template for how other professional fields might package expertise for agents.

Sources: arXiv:2609.00065, GitHub — K-Dense-AI/scientific-agent-skills

4. MASkills shows multi-agent skill libraries can improve themselves without human curation

A September 2 paper, MASkills: Continual Skills Optimization for Multi-Agent LLM Systems, proposes a pipeline that lets a team of LLM agents refine, induct, consolidate and prune their own shared skill library over time, using skill-conditioned credit assignment and hierarchical credit aggregation to work out which skills actually helped across the team's task history. Tested on HotpotQA, LoCoMo and GAIA, the approach treats skills as a more actionable memory unit than raw experience logs, since a skill specifies not just what happened but when to act, how to act, and which tools to reach for. It's a research-stage answer to a problem every team running skill libraries in production already has: skills accumulate faster than anyone can manually prune or improve them.

Sources: arXiv:2609.02094, arXiv (HTML)

5. Google quietly takes Gemini Enterprise's in-app skill authoring to general availability

Google Cloud's release notes now list the skills feature in Gemini Enterprise as generally available, gated behind an account-manager allowlist, letting end users create and use skills — Python- and Bash-executing procedures — directly inside the app rather than through a separate builder. The update also corrects an earlier release note: the previously announced "Enable skills" toggle for administrators was never actually shipped, and Google says it will update the notes once that control exists. Compared to Anthropic's and GitHub's skill ecosystems, the Gemini Enterprise rollout is deliberately narrow — GA but allowlisted, admin controls still incomplete — a sign Google is treating in-app skill creation as higher-risk than read-only skill use.

Sources: Google Cloud — Gemini Enterprise skills docs, Google Cloud — Gemini Enterprise release notes
