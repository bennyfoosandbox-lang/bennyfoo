1. Copilot CLI 1.0.117-3 stops an MCP approval from also approving built-in actions, and asks before each extension in autopilot

GitHub put out two more Copilot CLI 1.0.117 pre-releases on 26 Nov: 1.0.117-2 at about 02:00 UTC and 1.0.117-3 at about 20:17 UTC. The 1.0.117-3 fix with the most effect on safety is about approvals. Approving an MCP server's tools for a session or a folder used to also approve Copilot's own built-in requests, such as shell commands or memory writes, when the server's name matched a built-in permission type. Now it covers only that server's tools, and the approval still holds after a session resumes. Other changes: autopilot now asks before starting each extension instead of blocking them all; rejecting a Forge draft puts back the skill's original binary files and keeps edits made after generation; the CLI starts without plugins, and leaves the file alone, when config.json can't be read; and /mcp commands match server names in any case. Version 1.0.117-2 makes PowerShell hooks on Windows keep native exit codes, so exit code 2 counts as a warning or denial, not a failed hook. These are pre-releases. 1.0.116 is still the latest stable version.

Sources: Copilot CLI 1.0.117-3 release notes, Copilot CLI 1.0.117-2 release notes

2. Qwen Code 0.28.7 runs mods written for Claude Code 2.1.332 and adds a per-workspace Skills and MCP menu

Qwen Code published two stable releases on 26 Nov. Version 0.28.7 (about 18:00 UTC) includes PR #18435, so mods written for Claude Code 2.1.332 now load, register their commands and draw their status band. Command aliases, terminal-only commands and the new Progress element are supported. Hooks on the 25 event names added in 2.1.332 load but don't run, and print a one-line message instead of crashing. Before this fix, one such hook made the session exit with an error. The same release gives each trusted workspace in the Web Shell sidebar its own menu for MCP, Skills, Extensions, Channels and Settings (PR #18140). Earlier that day, 0.28.6 let commands run by extensions, and hook and MCP approvals in managed agents, wait for a decision without blocking the session (#18166, #18236). For teams that use more than one agent, this is a concrete step toward one set of extensions that works in both tools.

Sources: Qwen Code v0.28.7 release, Qwen Code PR #18435 (Claude Code 2.1.332 mods), Qwen Code PR #18140 (Web Shell workspace menu), Qwen Code v0.28.6 release

3. Google corrects its API Gateway skills, including the one-command lockdown we reported on 22 Nov, and hardens its Kueue troubleshooting skill

On 26 Nov, Google's public skills repo fixed facts in its four API Gateway skills that didn't match how the product behaves (18 files, +400/-224). This revises a change we covered on 22 Nov. The single-command lockdown from that change is gone: gcloud run services update doesn't accept --no-allow-unauthenticated, which is a gcloud run deploy flag. The skill now waits until every gateway serves a config with backend auth, then removes the allUsers and allAuthenticatedUsers invoker bindings, and it has separate steps for 1st-gen functions. It also warns that an API-key scheme with an unsupported header name or location is silently ignored, so it now tells you to check that a call without a key gets a 401. A second commit takes gke-kueue-troubleshooting to v1.1.1 (+5,508/-1,203 lines). The skill now asks before it pip-installs PyYAML, no longer accepts logs piped from stdin, skips symlinks, and must tell you which logs it couldn't read. Both commits show skill maintainers testing their instructions against real behaviour after release, which is the check that keeps a skill from confidently automating a wrong command.

Sources: google/skills commit 6ec2bf5 (API Gateway skills), google/skills commit c75ad1a (gke-kueue-troubleshooting v1.1.1)

4. A new Google skill helps organization admins turn on Cloud Operator, and asks for explicit confirmation at every step

Google added cloud-operator-admin-setup 1.0.0 to its skills repo on 26 Nov (8 files, +630/-151). The skill is for organization administrators. It enables or restores Cloud Operator (shown in the console as Gemini for Google Cloud operations) for a whole Google Cloud organization. It then walks through agent memory, read-only versus read-and-write actions, data sharing and user access, ending with a summary of the final settings. The safety rules are unusually explicit. Enabling the service needs the user to answer Enable or Restore, even if they already asked to turn it on. Turning it off needs the user to type disable after a warning that agents and sessions will be deleted. Granting roles/geminicloudassist.user needs confirmation. The skill never recommends accepting terms or choosing a setting. The per-user cloud-operator-setup (now 1.3.0) and cloud-operator (now 1.4.0) skills were rewritten to send users to the admin skill when their organization has the service off or they lack access, which shows how one skill can pass work to another.

Sources: google/skills commit 6dc0d53, cloud-operator-admin-setup SKILL.md

5. Google ships a Google Home Developer plugin that installs the same skill and docs MCP server in six coding agents

On 26 Nov, Google's skills repo added a google-home-developer plugin (1.0.0, Apache-2.0, 13 files, +403 lines). It is listed in both the Claude Code and Codex marketplace files. The plugin contains one skill, finding-google-skills, and connects to Google's hosted Home Developer MCP server at homedevelopers.googleapis.com/mcp. That server searches official Google Home, Matter and OpenThread documentation and can query diagnostics for cloud-to-cloud smart home integrations. Public docs work without credentials, and an API key gives dedicated quota. The diagnostics and gated Partner Program docs need OAuth or Application Default Credentials. The plugin ships install files for Antigravity, Claude Code, Codex CLI and Gemini CLI, and for VS Code/Copilot and Cursor through .mcp.json plus an AGENTS.md routing file. It's a clear example of a vendor packaging one skill and one MCP server once, for every major agent.

Sources: google/skills commit c413c1f, google-home-developer plugin folder, Google Home Developer MCP Server docs, MCP reference: homedevelopers.googleapis.com
