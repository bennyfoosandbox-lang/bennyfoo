1. Claude Code 2.1.319 fixes skill hot reload and adds a /claude-api latency-optimize command

Anthropic shipped Claude Code 2.1.319 on 6 November with two skill-facing changes. A hot-reload bug in .claude/skills is fixed: a file that was deleted just after it appeared, and then returned, could be missed, so edits made while you iterate on a skill are less likely to leave stale content loaded. The bundled /claude-api skill gets a new latency-optimize mode that finds where your Claude API code makes people wait and tries faster settings against your eval, and its Managed Agents guidance was corrected and its credential and permission examples tightened. The release also adds a permissions.denyInsteadOfPrompting setting so unattended runs deny a call instead of stalling on a prompt, and changes auto mode behind LLM gateways to ask or deny when the server check is unavailable.

Sources: Claude Code v2.1.319 release notes, Claude Code releases

2. Copilot CLI 1.0.107 and 1.0.108-0 make skill names case-insensitive and stop prompt paths from triggering skills

GitHub's Copilot CLI shipped 1.0.107 on 6 November and the 1.0.108-0 pre-release early on 7 November, both hardening how skills are matched. In 1.0.108-0, disabledSkills, skills.disable and skills.enable now match a skill name in any letter case, as invoking the skill already did, instead of silently doing nothing when the case differs. A path or URL route in a prompt, such as /docs/setup.md, no longer loads a skill named after its first segment as if you had invoked it, which removes a surprising accidental activation. The pre-release also warns when a selected custom agent's configured skills are missing or can't be loaded, and stops sending an internal message field on skill and tool messages to OpenAI-compatible providers. These are small fixes, but they target the failure mode that makes a skill library feel unreliable: skills that quietly don't behave as configured.

Sources: Copilot CLI v1.0.108-0 release notes, Copilot CLI v1.0.107 release notes, Copilot CLI releases

3. Agent skills are the new supply-chain dependency, argues Cloudsmith, citing 341 malicious skills out of 2,857 audited

Artifact-registry vendor Cloudsmith published a post on 6 November arguing that skills, which carry instructions and scripts an agent acts on, now deserve the same governance as npm packages or container images. Its case is that skills arrive from Git repositories, public catalogs and individual laptops with no single checkpoint, so platform and security teams can't see versions, checksums or pull history. It points to at least four independent research teams documenting waves of malicious skills on ClawHub since February 2026, including Koi Security's finding of 341 malicious skills among 2,857 audited. The proposed fix is routing skills through a registry like any other dependency. It is a vendor pitch, but the numbers it cites are a useful baseline for anyone deciding how freely a team should install community skills.

Sources: Cloudsmith: Agent skills are the newest dependency in your software supply chain

4. Skillware paper: equipping small models with modular skill bundles cut token use by up to 84.8%

A new arXiv paper submitted 5 November, “Don't Prompt Your Agents. Equip Them,” proposes Skillware, an open framework of versioned capability bundles that separate the model's planning from deterministic execution. The author positions it against the SKILL.md format used by Claude Code and Cursor, arguing that agents fail in production when they have to write code, guess payloads and memorize constraints on the fly. Across 23 models and 368 benchmark conditions, the paper reports that equipping small local models (3B to 8B parameters) with Skillware cut token usage by up to 84.8% and inference cost by up to 97.3%, and eliminated parameter errors. These are single-author, preprint results on the author's own benchmark, so treat them as a direction rather than a settled finding, but they support the productivity argument for packaging repeatable work as skills.

Sources: arXiv 2611.07652v1: Skillware

5. Adversa's November roundup: a leaky official OpenAI skill, scanners fooled by bytecode, 400 confirmed malicious skills (from 4 Nov)

Adversa AI's 4 November roundup of agent-skill security research is slightly older than 24 hours but unreported here and the most concrete security digest this week. It describes an official OpenAI render-deploy skill that named a non-Render domain for private services; Codex wrote it into generated deployment config as the default internal address, and once that domain was registered as a sinkhole, real services sent it calls carrying tokens. It also summarizes a scanner that flagged 620 of 150,108 skills across seven public registries, 400 confirmed malicious by manual review, and a “PyCache trap” in which benign source paired with a substituted bytecode cache evaded seven scanners with 94–100% attack success across 100 skills. The practical takeaway for productivity users is to read bundled scripts, not just SKILL.md, before enabling a third-party skill.

Sources: Adversa AI: Agent skill security, November 2026
