1. Claude Code v2.1.265 adds folder-of-plugins loading and fixes two skill/subagent prompt-cache bugs

Anthropic shipped Claude Code v2.1.265 on 8 September 2026 with a batch of changes aimed squarely at teams running many skills and plugins at once. The headline addition is --plugin-dir, which points at a folder of plugins and loads every child folder that has a manifest, picking up additions or removals live while the session runs — useful for anyone iterating on an internal plugin/skill collection without reinstalling each one. On the bug side, forked skills (sessions started with context: fork) were silently failing to stream their kickoff prompt, which broke visibility into what a forked skill was actually doing under --forward-subagent-text; that is now fixed. A subtler fix addresses agent teammates and resumed subagents dropping their preloaded-skill hook context out of the prompt prefix on later turns, which was quietly breaking prompt-cache reuse for that agent and driving up cost and latency on long-running skill-heavy sessions. None of this is a headline feature, but it is exactly the kind of plumbing work that determines whether a skills-based workflow with dozens of subagents stays fast and cheap as it scales.

Sources: GitHub Release v2.1.265, Claude Code changelog

2. SkillAdam borrows Adam's optimizer trick so skill self-evolution stops erasing its own progress

A 8 September 2026 arXiv paper, SkillAdam, tackles a specific failure mode in systems that let agents rewrite their own SKILL.md files from execution feedback: heuristic update rules tend to either overwrite a correction that was actually working, or make revisions too large or too small relative to how consistent recent improvements have been. The authors borrow the core idea behind the Adam optimizer from deep learning and adapt it to discrete, non-differentiable skill text — an "optimization memory" accumulates prior problems and the outcomes of past fix attempts so a good correction persists instead of being clobbered by the next iteration's local feedback, while a volatility-driven edit budget widens or narrows how much a revision is allowed to change based on how stable recent gains have been. Across seven benchmarks spanning short- and long-horizon tasks, SkillAdam reaches state-of-the-art performance with visibly more stable optimization curves, using substantially fewer iterations and lower cost than prior self-evolution methods. For teams betting on skills that improve themselves over time rather than being hand-maintained, this is a direct answer to the "it works today but regresses on the next run" complaint that dogs earlier self-evolving-skill approaches this digest has tracked.

Sources: arXiv:2609.08944 (abstract), arXiv:2609.08944 (full text)

3. CrowdStrike's Falcon Guardian starts tracing skill use to the system actions it causes

CrowdStrike introduced Falcon Guardian on 1 September 2026 at its Fal.Con conference in Las Vegas, an AI Detection and Response (AIDR) product that moves enforcement to the endpoint where agents actually execute, rather than only governing the instructions an agent is given. The Falcon sensor builds a live inventory of known and shadow AI agents running on Windows and macOS, records who deployed each one and its security posture, and — most relevant to this digest — links agent behavior to endpoint telemetry by tracing prompts, identities, tool calls, and skill use through to the downstream system actions they trigger, producing something like an execution graph for each agent session. It ships alongside Agent Access Controls, which let admins define which agents may run on managed endpoints and block unauthorized ones outright, plus runtime detection for attacks on agents and malicious agent behavior more broadly. CEO George Kurtz framed the pitch directly against governance-only approaches: "governance alone can't stop an agent already in motion," positioning endpoint-level skill and tool-call tracing as the missing enforcement layer underneath the policy layer that most agent security tooling has focused on so far.

Sources: CrowdStrike press release, SiliconANGLE, BizTech Magazine

4. Copilot in SharePoint makes Skills portable across sites and OneDrive, and adds evaluations to measure them

Microsoft's "What's New in Copilot in SharePoint: September 2026" roundup describes reusable Skills that can now follow a user across SharePoint sites and OneDrive rather than being locked to wherever they were first created — the preferred formats, standards, and repeatable working patterns a team or individual builds travel with them instead of needing to be rebuilt per site. Alongside portability, Copilot gains the ability to run evaluations against a Skill, giving teams a way to measure whether a given Skill is actually improving outcomes and to catch regressions before they spread across every site that reuses it — a governance gap this digest has flagged in SharePoint's own Skills feature since it reached public preview earlier this year. The same update adds tenant-specific HTML guidance that any AI assistant (Cowork, Scout, GitHub Copilot, Copilot Studio, or otherwise) can be pointed at for up-to-date instructions on building interfaces that work safely inside SharePoint's sandbox, closing off a class of "the agent built something that looks right but breaks in the SharePoint shell" failures. Together, portability plus measurement is the same pattern this digest has watched play out on Claude and GitHub Copilot: once an ecosystem has enough Skills in production, the next investment is always in making them measurable and shareable rather than in adding more of them.

Sources: Microsoft Community Hub

5. OpenClaw 2026.9.1 gives every user a personal skill library and teaches Doctor to untangle broken Skill Workshop migrations

OpenClaw's 2026.9.1 release, out 3 September 2026, follows up on the sprawling 2.0 launch from late August with a more targeted addition: personal skill libraries on shared Gateways. Any user on a shared Gateway can now run openclaw skills library to keep their own skills alongside the workspace-wide set, import skills from ZIP archives, and share or publish specific skills per identity rather than only at the whole-team level — a direct answer to the "everyone on this Gateway is stuck with the same skill set" complaint that shared-team deployments of OpenClaw have carried since 2.0. The release also hardens Skill Workshop, OpenClaw's persistent agent-owned collection for comparing and curating skill instructions across workspaces introduced with 2.0: Doctor can now recover incomplete Skill Workshop proposal migrations that previously left an installation stuck between versions, preserving recoverable files and letting them converge safely on a later Doctor run instead of requiring a manual fix. It's an incremental release rather than a flashy one, but it directly targets the multi-user skill-management friction and the version-upgrade fragility that reviewers flagged as OpenClaw 2.0's rough edges just two weeks ago.

Sources: OpenClaw GitHub release v2026.9.1, Releasebot: OpenClaw updates
