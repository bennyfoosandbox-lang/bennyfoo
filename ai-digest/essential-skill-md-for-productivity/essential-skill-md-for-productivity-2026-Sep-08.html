1. Claude Code ships /skill-doctor, turning skill bloat into a one-command fix

Claude Code v2.1.261, released 4 September 2026, adds a new /skill-doctor command that lists every skill currently loaded into a session alongside how often each has actually fired and how many context tokens it costs per turn — the same release run also closed a plugin symlink path-traversal hole (v2.1.260, 3 September) and shipped further reliability fixes (v2.1.263, 6 September). The pitch is squarely about the "essential skills" question this digest tracks: skills are cheap to install but not free to keep, since a loaded-but-never-triggered skill still eats context on every single turn. Early hands-on coverage backs that up — one widely shared write-up ran the command across a real setup and found "most skills are dead weight," with several loaded skills never once invoked despite sitting in the context budget the whole time. For teams that have spent the past year accumulating skills the way they once accumulated browser extensions, this is the first built-in tool to actually audit and prune that pile rather than just add to it.

Sources: Claude Code changelog, Joe Njenga on Medium, Julian Goldie: Skill Doctor

2. OpenAI's Codex CLI can now import — and keep syncing — Cursor's own skills

Codex CLI 0.147.0 extends its /import command so it pulls in Cursor-managed skills directly rather than only Claude Code conversations, and — more notably for repeat use — re-running /import against a session already imported now updates that entry in place instead of spawning a duplicate in Codex's thread list. That turns what used to be a one-time migration trick into an ongoing way to keep a team's skills aligned across Cursor and Codex without manual bookkeeping, reinforcing the cross-harness portability that SKILL.md was designed to enable in the first place. The coverage flags a real caveat, though: the feature only runs inside a local, embedded TUI session (not Codex Cloud or the app-server daemon), and an imported skill whose instructions assume a Cursor-specific panel or mechanic doesn't become meaningful just because the file now lives somewhere Codex reads it — reviewers are told to re-open each imported SKILL.md and check for exactly that. It's a small but concrete data point in the "write once, run on any harness" thesis this digest has followed since Anthropic opened the SKILL.md spec.

Sources: Digital Applied, Get Claude Skills, Vibe Coding Academy: Codex CLI 0.147.0

3. New attack manipulates which skill an agent picks — without ever writing an explicit instruction

A 2 September 2026 arXiv paper, "Implicit Manipulation for Skill Selection in LLM Agents with Semantic Matching," identifies an attack surface one step upstream of the usual "malicious skill body" story this digest has covered all year: even when a user's prompt and a skill's description both look benign in isolation, their semantic relationship can be deliberately shaped so a routing model favors an attacker-chosen skill anyway. The authors' method, ISM, jointly tunes a target skill's metadata and a set of reusable prompt phrasings across three stages — broadening semantic coverage, sharpening the target skill's distinctiveness relative to competitors, and keeping the prompt wording natural — and it lifts the average target-selection rate from 15.2% to 63.5% across four task domains and eight selector models. The part that should worry marketplace operators most is detectability: human reviewers caught explicit steering attempts 91.4% of the time, but caught ISM's implicit version only 2.9% of the time, meaning the routing layer itself — not just the skill body — needs its own defenses.

Sources: arXiv:2609.02035 (abstract), arXiv:2609.02035 (full text)

4. A new framework lets computer-use agents keep the skills they learn instead of forgetting them each run

Researchers from Zhejiang University and the University of Electronic Science and Technology of China posted "From Interaction Traces to Persistent Skills: Online Evolution for Computer-Use Agents" on arXiv on 4 September 2026, addressing a gap this digest keeps circling back to: procedural knowledge a computer-use agent picks up mid-task is usually thrown away the moment the rollout ends, rather than carried into the next one. Their framework converts raw interaction trajectories plus evaluator feedback into a persistent, versioned library of reusable procedures, with each iteration executed against a frozen snapshot of that library so evidence-guided updates only take effect in later runs — no model retraining required. It's a research prototype rather than a shipped product, but it's a direct, on-topic complement to this digest's earlier coverage of Google's WikiSkill and SKILL.state: another team independently converging on "let the skill library evolve on its own" as the fix for agents that keep re-learning the same GUI workflow from scratch.

Sources: arXiv:2609.04869 (abstract), arXiv:2609.04869 (full text)

5. Skill-as-API keeps a coding agent's skill logic off the wire, closing an IP and prompt-injection gap in multi-agent coordination

"Skill-as-API: Confidential Multi-Agent Coordination for Agentic Software Engineering," posted to arXiv on 1 September 2026 ahead of the Agentic Software Engineering (SE 3.0) workshop in Jeju, targets a quieter problem than the usual malicious-skill headline: as coding agents start discovering and invoking each other's specialized skills over protocols like MCP and A2A, those protocols publish a skill's full description and typed schemas to every peer and offer no way to keep a skill's existence or its wrapped system prompt off the wire — leaking exactly the intellectual property a team may have spent months tuning. Skill-as-API instead limits what's public to a skill's name, description, typed input/output schema, and a trust tier, while the actual skill body stays closure-captured inside the owner's own process and never crosses the network; four additional layers add access control and narrow the prompt-injection surface structurally rather than by filtering content after the fact. As multi-agent "skills calling skills" setups move from demos toward production, this is an early, concrete answer to a confidentiality problem that most current coordination standards simply don't address.

Sources: arXiv:2609.01677 (abstract), arXiv:2609.01677 (full text)
