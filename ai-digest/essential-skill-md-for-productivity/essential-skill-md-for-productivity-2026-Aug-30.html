1. Claude Code v2.1.251 closes a symlink-swap escape and a plugin path-traversal hole in one 71-change release

Anthropic shipped Claude Code v2.1.251 on August 28 — a dense release spanning 71 fixes and additions, several of which harden exactly the surface a SKILL.md-driven session depends on. The Read, Write, and Edit tools could previously be tricked into reading or writing outside the approved working directory if a symlink was swapped in after the permission check had already run; that path is now closed. A companion fix rejects plugin marketplace entries whose declared command path points outside the plugin's own directory, throwing a path-traversal error instead of silently following it, and a third fix stops background sessions from occasionally starting with no plugin skills loaded at all when another Claude Code process happened to be refreshing the plugin marketplace at the same moment. On the productivity side, the release adds a per-session prompt-cache breakdown to /cost (hit ratio, misses, tokens re-cached) and new PreModelSwitch/PostModelSwitch hooks for auditing model changes mid-session. Taken together, it's the third consecutive week Anthropic has spent hardening the skill/plugin execution boundary rather than adding new skill capability.

Sources: Claude Code changelog, GitHub release v2.1.251

2. Google's WikiSkill lets a 9B model outperform a 27B model by writing its own wiki of lessons learned

Google Research published WikiSkill on August 28, a framework that co-evolves an agent's executable skills with a persistent, wiki-shaped knowledge base instead of collapsing raw experience, accumulated knowledge, and skill text into one artifact the way most self-evolving-skill systems do. An Inference Agent runs task rollouts on the current skill set, a Wiki Maintainer consolidates the results into structured knowledge, a Skill Proposer drafts skill updates from that wiki plus the raw traces, and a gating-and-rollback step keeps a bad proposed update from sticking. Tested across five very different benchmarks — math reasoning, web search, spreadsheet management, long-context QA, and embodied interaction — WikiSkill improved scores by an average of 12 points, including a jump from 33.0% to 72.6% on LiveMathematicianBench and 50.5% to 76.6% on SpreadSheetBench, and the evolved skills transferred well enough across model families that a 9B model equipped with them beat a 27B model without them. For anyone maintaining a library of SKILL.md files by hand, it's a concrete demonstration that letting agents write and refine their own skills from real usage can beat both static skill files and raw scale.

Sources: arXiv abstract, arXiv full text, The Decoder

3. SKILL.state swaps the ever-growing chat transcript for a mutable execution state — and accuracy goes up while token spend drops

A second paper published the same day, SKILL.state, targets a different failure mode in long-running skill execution: most agent runtimes track progress by continually appending observations, actions, and reasoning traces to the conversation history, which degrades latency and eventually poisons the context on long tasks. SKILL.state replaces that append-only history with an explicit, mutable execution state — at each step the model sees only the immutable skill specification, the current structured state, and the latest observation, with intermediate reasoning discarded the moment a validated state update is produced, so the prompt never grows with execution history. Across diverse datasets, models, and execution environments the authors report improved task accuracy alongside a substantial cut in cumulative token consumption, directly addressing the two most common complaints about long-horizon SKILL.md-based agents: they slow down and start hallucinating the longer a task runs. Between this paper and WikiSkill, both released the same day, skill-runtime architecture — not skill content — is emerging as this week's research focus.

Sources: arXiv abstract, arXiv full text

4. Claude's Skills and Files APIs drop their beta headers — and quietly change what deleting a skill does

Starting with Python SDK 1.2.0, TypeScript 0.122.0, Go 1.68.0, Java 2.59.0, Ruby 1.67.0, and C# 12.44.0 (released August 27), client.beta.skills and client.beta.files stop sending the skills-2025-10-02 and files-api-2025-04-14 beta headers and return the same shapes as the non-beta client.skills and client.files — moving the Skills API from beta to its production surface. Two changes are worth flagging for anyone building on it: the beta Messages type BetaSkill (the container-skill reference) is renamed BetaContainerSkill, and client.beta.skills.delete() now deletes a Skill together with all of its versions rather than just the one requested — a behavior change that could silently remove more than a team expects if their code was written against the old, single-version delete semantics. Requests that still send the old beta headers keep the old shapes for now, giving teams a migration window, but Anthropic's own documentation now steers new integrations toward the non-beta path.

Sources: Claude Platform release notes, Skills API migration guide

5. GitHub Copilot CLI retires its old /plugins command and legacy skills picker for good

GitHub shipped Copilot CLI v1.0.81 on August 27, folding the standalone /plugins command into /plugin, /mcp, and /skills (with /subagents and /instructions taking over agent- and instruction-management duties), and a same-week point release went further, removing the PLUGINS_DASHBOARD opt-out along with the legacy skills picker it had been keeping alive. Going forward, /skills, a bare /mcp, and /mcp show with no server name all open the same unified dashboard, while /mcp config still opens the dedicated MCP setup wizard — a command-surface cleanup that lands the same week GitHub's Copilot app Customize tab (covered in this digest on August 29) reached general availability for browsing skills, MCP servers, and plugins in one place. For teams standardizing SKILL.md-style workflows across several coding agents at once, it's one fewer inconsistent command surface to document and support.

Sources: GitHub Copilot CLI releases, Havoptic release tracker
