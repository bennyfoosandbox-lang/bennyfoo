1. The skills CLI 1.8 adds a verifiable lock file, tag pinning and a programmatic API

The open-source skills CLI behind npx skills add shipped 1.8.0 and 1.8.1 on 10 November, its largest release in months. The headline change is lock file v2 with a portable, verifiable computedHash, so a team can check that the skills restored from skills-lock.json on one machine match those on another; direct downloads are now locked too, so update and restore can fetch them again. owner/repo@v1.2.3 now checks out that tag instead of the default branch, the installer checks every target before writing and verifies blob snapshots against the GitHub tree, and remove no longer deletes files it did not install. 1.8.0 also exposes a programmatic API and installs Antigravity global skills into ~/.gemini/config/skills. For anyone sharing skills across a team, pinned versions plus hash-checked restores turn a folder of copied files into something closer to a reproducible dependency.

Sources: vercel-labs/skills releases (v1.8.0, v1.8.1), skills on npm

2. Copilot CLI 1.0.109 keeps repository-disabled skills off, and 1.0.110 pre-releases fix skill toggles

GitHub Copilot CLI 1.0.109 went stable on 10 November. On the skills side it keeps skills a repository has disabled switched off in /skills when you trust a folder for the current session only, so a quick one-off trust no longer re-enables skills the repo owner turned off; it also promotes the earlier fix that keeps selected skill problems visible in long lists. Two pre-releases followed the same day: 1.0.110-0 makes the MCP server and skill enable/disable commands report success correctly, lets MCP tool results that carry a top-level key such as skills reach the model, and shows the enabled state that an organization's managed settings enforce for built-in plugins. 1.0.110-1 makes plugin toggles honor repository-controlled live plugin settings. The common thread is that repository and organization skill policy now holds across trust prompts and toggles.

Sources: Copilot CLI changelog, Copilot CLI releases, Copilot CLI v1.0.109

3. Jane Street publishes its first public skill: a strict Socratic tutor

Jane Street has opened a public janestreet/agent_skills repository under the MIT license, and its first skill is not a trading tool but socratic-tutor, a SKILL.md that turns an agent into a strict personal tutor for any topic. It starts with a diagnostic, builds a skill map with levels 0 to 5, asks one question at a time, schedules spaced review and ends with a final assessment. The README says it works in any coding agent that reads the common SKILL.md format, or pasted into a plain chatbot's system prompt. The repo already has about 3.9k stars and 233 forks, which suggests a strong appetite for skills that help people learn, not only skills that write code. This item dates from early November (reported 3 Nov) and is included because the 24-hour window was thin; it has not appeared in earlier digests.

Sources: janestreet/agent_skills on GitHub, Dealroom news note

4. Qwen Code adds Skill ZIP installs, bulk activation and a warning for stacked skills

Alibaba's Qwen Code shipped a cluster of skill-management features across 0.26.9 (6 Nov) and 0.27.0 (7 Nov). Skills can now be installed from ZIP archives through new daemon API routes, the TypeScript SDK (from a File, Blob, bytes or a host path) and an upload button on the WebShell Skills page, with installation receipts to check after a failure and recovery backups for larger archives. A new PUT /skills/activation endpoint enables or disables between 1 and 100 user skills in one request. 0.27.0 adds a warning in non-interactive, ACP and channel runs when a prompt stacks more than five skills, a guard against context bloat. Together these make skills manageable as packaged artifacts for teams running Qwen Code as a service. Both releases are 4-5 days old (fallback window).

Sources: Qwen Code CHANGELOG, Qwen Code v0.26.9, Qwen Code v0.27.0

5. OpenClaw 2026.11.2 stops Doctor from disabling skills whose binary lives on a paired node

OpenClaw 2026.11.2, released 8 November, changes how its Doctor repair tool treats skills with unmet requirements. Previously, Doctor would disable an enabled skill if a binary it needs was missing on the local machine, even when that binary was available on a paired node that could run the skill. Now the skill stays enabled in that case, and it can also stay enabled when another requirement is missing (PR #178665). For people who split OpenClaw across a laptop and a home server or other paired device, this stops a routine repair run from silently switching off skills that worked fine remotely.

Sources: OpenClaw 2026.11.2 changelog, openclaw/openclaw PR #178665, OpenClaw skills guide
