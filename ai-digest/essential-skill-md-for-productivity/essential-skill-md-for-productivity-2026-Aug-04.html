1. NVIDIA open-sources SkillSpector to triage agent skills before they're installed

NVIDIA released SkillSpector, an open-source, Apache-licensed scanner that reads a SKILL.md bundle — as a directory, zip, single file, or Git URL — and hands back a 0–100 risk score plus a verdict before you install it. A fast static pass checks 64 vulnerability patterns across 16 categories (prompt injection, data exfiltration, privilege escalation, hidden instructions, tool poisoning, dangerous code execution), with an optional LLM semantic pass to cut false positives and explain findings in plain language. The research behind it scanned 42,447 skills pulled from major marketplaces and found 26.1% carried at least one real vulnerability, with 5.2% showing likely malicious intent — hard numbers that make curating an "essential skills" list inseparable from a pre-install security check. For anyone building a personal or team skill library, it's a free, scriptable gate to run before adding a new skill, rather than trusting a marketplace's own badge.

Sources: Help Net Security, GitHub — NVIDIA/SkillSpector, NVIDIA Skill Documentation

2. Research: agents silently skip 44% of the steps their own skill mandates

A University of Michigan team (Dantanarayana, Kashmira, Tang, Mars) found that when an LLM agent runs a prose SKILL.md through an ordinary tool-calling loop, it re-derives its own control flow every single time — and across 30 skills and two model generations, it completed only 56% of the steps its own skill actually mandated, even while producing output that passed downstream checks. Their proposed fix, SIGIL, compiles a prose skill into an executable harness via a typed intermediate representation (AG-IR) that separates what the model decides from what code enforces, so mandated verification steps can't quietly get dropped. It's a direct challenge to the working assumption behind most "essential skill" advice — that a well-written SKILL.md alone guarantees the agent follows it — and suggests reliable, repeatable productivity workflows may need partial compilation, not just better prose. This is early-stage research (submitted 29 July), noted here slightly outside the usual 24-hour window because it bears directly on skill reliability.

Sources: arXiv:2607.27309, Full text (HTML)

3. HiSkill proposes graphing skills instead of just listing them

As personal and team skill libraries grow past a handful of files, agents increasingly retrieve the wrong skill or miss dependency and ordering relationships between them. HiSkill organizes a skill library into a hierarchical graph — skill nodes, atomic-action nodes, and typed edges for decomposition, sequencing, compatibility, support, and recovery — instead of the flat, independently-retrieved lists most skill managers use today. At inference time it pulls a compact, task-relevant subgraph rather than a single best-match skill, so an agent can see how the retrieved skill relates to others it may need to chain or fall back on mid-task. For anyone curating a large "essential skills" set, it's an early preview of where skill management goes once a flat directory of SKILL.md files stops scaling. Submitted 28 July; included here as a widened-window item since nothing this specific to library-scale skill organization has surfaced in this digest before.

Sources: arXiv:2607.25853, Full text (HTML)

4. "Skill Leakage" research: a paid skill's behavior can be reverse-engineered from its outputs

As skill marketplaces increasingly monetize proprietary SKILL.md files behind cloud-hosted agent interfaces, a new paper shows that hiding the skill's text doesn't hide what it does: recurring "skill signatures" in an agent's execution trajectory form a behavioral side channel. The authors' SigLeak framework reconstructs a proprietary skill's procedure from trajectories elicited by ordinary, benign queries — no reference answers, no success labels, and no access to the underlying skill file required. That's a direct challenge to the business model behind paid, curated skill marketplaces (Agensi, SkillHub, and others charging for vetted skills), since it suggests the underlying know-how can leak even when the marketplace never exposes the file itself. Submitted 28–30 July; included as a widened-window item for its relevance to the "curated vs. free" economics running through this space.

Sources: arXiv:2607.25560, Full text (HTML)
