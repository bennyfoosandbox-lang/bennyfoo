1. Codex 0.164 and 0.165 rework how skills are refreshed and read

Codex CLI 0.164.0 (23 Oct) moves TUI skill refreshes and workspace commands onto explicit directories, routes skill reads by alias source, and gives app-server skill catalogs frozen cloud snapshots. Those changes make it more predictable which copy of a skill an agent actually loads when the same skill exists in several places. Release 0.165.0 (27 Oct) is mostly about a built-in Google Cloud Vertex AI provider and new model-catalog entries, and its notes list no skills change, so the skill work sits in 0.164. The sources are a changelog and an aggregator, so check the official notes for the exact wording.

Sources: OpenAI Codex changelog, Releasebot: Codex updates

2. Gemini CLI 0.66.0 hardens SKILL.md frontmatter parsing

Gemini CLI v0.66.0, released 27 Oct, includes a fix that hardens parsing of SKILL.md frontmatter for single-line descriptions. This matters because an open GitHub issue from April reported that skills with a single-line description were not discovered until the author switched to a folded multi-line block. I could not confirm that this release closes that exact issue. The fix shows how fragile the name-and-description header is, since a parser quirk can make a skill silently invisible to the agent. Releasebot's summary of the same release does not mention skills, so the GitHub release page is the primary source.

Sources: google-gemini/gemini-cli releases, Releasebot: Gemini CLI updates

3. Claude Code 2.1.311 stops finished sub-agent skills from running twice

Claude Code 2.1.311, first seen by Releasebot on 26 Oct, fixes a case where a skill that had already finished in a sub-agent ran a second time when a cloud or background session restarted. A re-run can repeat side effects such as commits, API calls or messages, so this is a real reliability fix for anyone delegating skills to background sessions. A separate note in the Oct 27 listing says skills were not being found after a Bash cd deeper into a git repository, and that this has since been fixed. Releasebot is an aggregator, so confirm version numbers against Anthropic's own changelog.

Sources: Releasebot: Claude Code updates, Releasebot: Anthropic release notes

4. Cursor's Cloud Agent now warns when a SKILL.md is broken

In the week of 19 Oct, Cursor began showing a warning in Cloud Agent runs naming any skill whose SKILL.md has invalid frontmatter, no description, or cannot be read. Before this, the agent quietly skipped such a skill or was unlikely to pick it, so authors had no signal that a skill was dead. Cursor's docs say a skill with no description can still be invoked by name. Earlier local checks (v2026.10.08) already flag skills that break the spec limits, such as a name over 64 characters or a description over 1,024. This item is about ten days old but had not been covered before.

Sources: Cursor release notes, Cursor Agent Skills docs

5. Copilot CLI 1.0.103 tweaks skill install links, marketplace sources and allowed-tools

A community tracker that follows Copilot CLI skill behaviour reports that v1.0.103 (22 Oct) adds ghapp:// install links, git-subdir marketplace sources, and fixes how comma-separated allowed-tools are handled, alongside search, web and todo tool aliases. Together these make skills easier to distribute from a subfolder of a repo and to restrict tools reliably. The detail comes from a third-party pull request that summarises the release notes, not from GitHub itself, so treat specifics as unverified. The later 1.0.104 and 1.0.105 releases on 27 Oct focus on model fallback and assisted permissions rather than skills.

Sources: github/copilot-cli releases, CowboyLogic/ai-dev PR #126 (weekly Copilot skills refresh)
