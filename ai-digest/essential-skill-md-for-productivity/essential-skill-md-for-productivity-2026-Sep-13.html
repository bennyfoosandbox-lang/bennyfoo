1. Claude Code v2.1.269 and v2.1.270 close two silent-failure gaps in skill and plugin loading

On 11 and 12 September, Anthropic shipped Claude Code v2.1.269 and v2.1.270, two releases squarely aimed at making skill and plugin loading fail loudly instead of silently. v2.1.269 fixes plugins that were silently skipping a default monitors file or a root SKILL.md that could not be checked — a bug that meant a broken skill file could vanish from a session without any warning — and sharpens the Skill tool's "Unknown skill" error to name the full plugin-qualified skill name when a bare name matches exactly one plugin skill. It also closes a local-user file-permission gap in extracted plugin archives and stops abandoned LSP servers (e.g. rust-analyzer) from lingering after a session ends. v2.1.270, pushed the next day, fixes a regression introduced in .269 that made read-only git commands in Bash unexpectedly re-prompt for permission mid-session. For teams running dozens of SKILL.md files across plugins, this is exactly the class of bug — silent skips, misleading errors — that erodes trust in an unattended skill library.

Sources: Claude Code changelog, v2.1.269 release, v2.1.270 release, Claude Code Changelog on X

2. COBRA-Skills cuts the cost of teaching agents new skills by more than half

A 10 September arXiv paper introduces COBRA-Skills, a framework that treats each candidate skill as an arm in a contextual bandit — scored with a neural reward predictor plus a LinearUCB uncertainty bonus — so only the most promising skill is executed and evaluated each round, instead of exhaustively testing every candidate the way prior skill-optimization pipelines do. Across six heterogeneous agent benchmarks (question answering, spreadsheet manipulation, visual document understanding, math reasoning, social reasoning and embodied decision-making) and three target models, it matches or beats existing methods like SkillOpt while cutting optimization cost by 55–58% and needing only 50 unique task examples per benchmark to converge. For anyone curating an "essential skills" library at scale, this is a concrete recipe for growing and pruning a skill set without the execution-heavy trial-and-error that has made automated skill curation expensive.

Sources: arXiv:2609.11682, Full text (HTML), Pith summary

3. Repo-To-Skill distills 5,000 skills out of 1,000 ML GitHub repos — and lifts a benchmark score 134%

A 2 September arXiv paper, Repo-To-Skill, describes DisCo, a skill-powered research agent that mines the operational know-how buried in popular open-source repositories — the parts written for human readers and normally too large to reload during a task — and distills it into compact, verified SKILL.md-style procedures. Applied across the open ML ecosystem this produced the AREX-Skill Library: 5,000+ verified skills drawn from 1,000 widely used repositories, organized into 20 areas and 178 capability families. With the same GPT-5.5 backbone, research harness and execution budget held fixed, a skill-equipped agent scored 134.3% higher on MLE-bench, 34.4% higher on PaperBench, 9.2% higher on FrontierCS and 14.0% higher on PassNet than the identical agent without skills — one of the largest reported productivity swings yet from adding a skill library rather than a bigger model. The project ships an open GitHub repo and an npm-installable DisCo CLI, so the library is directly reusable rather than just a benchmark result.

Sources: arXiv:2609.02749, Full text (HTML), Hugging Face Papers
