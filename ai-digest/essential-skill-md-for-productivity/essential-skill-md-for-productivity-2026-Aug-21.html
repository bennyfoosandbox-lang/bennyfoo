1. New study explains why skills work — and pinpoints exactly when they stop

A paper posted August 14 (arXiv 2608.14036), "Demystifying Agent Skills: Why They Work—Until They Don't," normalizes 8,135 trial records into a taxonomy of three categories and twelve skill-use modes, and the headline finding reframes what a good SKILL.md is actually for: "procedural anchoring" — turning noisy past trajectories into a clean, stable sequence of steps — accounts for 65.7% of skill value, versus just 4.5% for injecting new facts the model didn't already know. In matched comparisons, skills outperform raw "workflow memory" (keeping full execution detail instead of a distilled procedure) by 6.06 points, confirming that distillation itself is the value-add, not just extra context. The paper's second finding is a caution for anyone building a large skill library: as a candidate pool grows from 5 to 100 skills, actual-use precision collapses from 29.6% to 3.3%, meaning retrieval — not skill quality — becomes the bottleneck at scale. Even when the right skill exists, agents still fail when it's retrieved for the wrong procedural context, invoked only superficially, or undermined by task-level blockers like timeouts, numerical precision, or missing dependencies that no skill file can paper over — a concrete argument for keeping personal and team skill sets small, distilled, and pruned rather than sprawling.

Sources: arXiv abstract, arXiv full text

2. Claude Code closes out its NTLM credential-leak hardening and fixes a skills hot-reload bug

Across three releases this week — v2.1.234 (Aug 17), v2.1.235 (Aug 18), and v2.1.236 (Aug 19) — Claude Code finished a multi-release security push that started earlier in August: remote file reads, session restore, CLAUDE.md includes, workflow scripts, and file uploads now all reject Windows NT-namespace ("\??\") paths, closing an NTLM credential-leak vector that malformed paths could previously exploit to bypass pre-approval file-access checks. The same run of releases tightened credential masking on relayed permission previews so commands, paths, and destinations can no longer be hidden from an approver, and fixed provider API tokens that weren't masking correctly when followed directly by shell delimiters. For anyone running a personal or team skill library day to day, two smaller changes matter more directly: v2.1.236 fixed skills failing to hot-reload after a session's working directory was deleted, and v2.1.234 added automatic session continuation when a claude.ai usage limit resets, so a long skill-driven task doesn't stall waiting for a manual nudge. v2.1.236 also added `notify_when_idle` to cross-session messaging, letting one Claude Code session ping another by name when it goes idle — useful for anyone running parallel skill-driven workflows across sessions.

Sources: GitHub Releases (v2.1.234), Claude Code changelog

3. Figma ships in-app skill authoring — describe a workflow once, the agent writes the SKILL.md

Figma announced on August 13 that its design agent and Figma Make can now author custom skills directly inside the product: a user describes a repeatable task — reviewing content against brand voice, checking a UI against a team's design standards, a specific audit or documentation pass — and the agent turns that description into a reusable Markdown skill file that follows the open Agent Skills specification. Skills are created from the chat sidebar or from Figma Make, and once created they stay available across every file, not just the one they were built in, so a skill written for one project's conventions travels with the user. It closes a loop that's been a recurring theme in this digest: SKILL.md authoring has mostly required leaving the product to hand-write a file, and Figma is now among the first major design tools to make "watch what I do, then package it as a skill" a first-class, in-app action rather than a separate workflow.

Sources: Figma Blog, Figma Help Center

4. Alipay turns merchant storefronts into agent-ready Skills and MCP tools at national scale

Alipay launched what it calls China's first full-stack agentic commerce platform on August 18, and the core mechanic is directly relevant to this digest: for merchants who already have digital operations but no AI capability, the platform automatically converts their existing pages, products, and service workflows into agent-ready Skills and MCP tools, lowering the barrier to AI adoption without requiring them to author anything by hand. Those Skills plug into Ah Bao, Alipay's consumer-facing "super agent" launched in June, which lets shoppers handle bookings, payments, and everyday services through natural conversation instead of navigating individual apps — and through Alipay's AHA interoperability protocol, a merchant's Skills reach consumers across phones, connected cars, and AI glasses, not just the Alipay app itself. The scale is the story: retail brands including KFC, Luckin Coffee, and Mixue Bingcheng, plus 16 automakers and phone brands representing over 70% of China's smartphone market, are already integrated, making this one of the largest production deployments yet of "business workflow as an agent skill" outside the developer-tooling world this digest usually covers.

Sources: Finextra, TechNode Global

5. Xsolla adds a CLI to its free agent-skill toolkit, taking game devs from empty project to live storefront in one session

Xsolla announced on August 11 that it has added a CLI to its AI Toolkit — a free, public library of agent skills published as SKILL.md files on GitHub that guides coding tools like Claude Code, Cursor, and Copilot through correctly integrating Xsolla's commerce API. Previously a developer still had to manually create a publisher account and generate API credentials before the skill-guided integration could begin; the new CLI automates that setup end to end — creating the account, generating credentials, and configuring webhooks from the command line — so a developer can go from a brand-new project to a working, reviewed web storefront in a single session. It's a small but concrete example of a pattern showing up across this digest: as skill libraries mature, the bottleneck shifts from "does a skill exist for this task" to "what still requires leaving the coding agent to do by hand," and toolkit builders are increasingly closing that gap themselves rather than leaving it to the user.

Sources: Business Wire
