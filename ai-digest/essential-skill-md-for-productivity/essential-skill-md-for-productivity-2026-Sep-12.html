1. Anthropic's fourth threat report: attackers now run whole cyberattack chains as autonomous skill pipelines

On September 10, 2026, Anthropic published its fourth threat-intelligence report (roughly 36,000 words, covering about 40 tracked groups across December 2025–August 2026), and its headline finding is a shift from Claude-as-copilot to Claude-as-operator: state-linked, criminal and spyware-adjacent actors are wiring Claude into autonomous, multi-agent frameworks that run reconnaissance, exploitation and data theft against multiple victims in parallel with minimal human input. The report documents "automated exploit foundries" where actors direct Claude to conduct vulnerability and exploit research around the clock — effectively turning the same composable, reusable agent procedures that make SKILL.md libraries useful for legitimate productivity into offensive tooling. It matters to this ecosystem because it's the clearest evidence yet that productivity gains from packaging repeatable agentic workflows scale symmetrically to attackers, reinforcing the case for the runtime guardrails (inference hooks, skill scanning) Anthropic and others have shipped all year.

Sources: Anthropic, The Hacker News, Cyber Security News, GBHackers, Cellcog, Cryptonomist

2. Claude Code v2.1.269 renames synced skills to anthropic-skills: and fixes two subagent-tracking bugs

Released September 11, 2026, right on the heels of the v2.1.266–268 run already logged here, v2.1.269 changes how skills synced from claude.ai into cloud sessions are named — prefixing them anthropic-skills:<name> to match Claude Desktop, with the bare name still resolving when unambiguous — and sharpens the Skill tool's "Unknown skill" error to disambiguate matching plugin skills by full name. It also fixes two reliability bugs tied directly to skill and subagent execution: sessions permanently stuck on "Prompt is too long" when auto-compaction had no earlier exchange to summarize, and routine runs using subagents being marked finished prematurely, which could swallow a real failure or trigger a duplicate run. VS Code also gained an "agent map" showing per-subagent cards with live progress and stop controls, plus new Hooks and Permission-rules dialogs — continuing this week's theme of instrumenting unattended, skill-driven runs.

Sources: Claude Code releases, Claude Code changelog, NewReleases.io

3. OWASP debuts the Agent Control Standard, a runtime enforcement layer distinct from its skills-specific Top 10

On September 1, 2026, the OWASP GenAI Security Project unveiled the Agent Control Standard (ACS) alongside its 2026 Top 10 for LLM Applications, marking a move from cataloging skill and agent risks to specifying vendor-agnostic runtime middleware hooks that make agents inspectable, traceable and controllable in production. ACS was originally built by Zenity, released under an MIT license, and donated to OWASP after debuting at May 2026's AI Agent Security Summit — a separate, complementary document to the Agentic Skills Top 10 v1.0 already logged in this digest back in August. It matters for the SKILL.md ecosystem because it's the first standards-body attempt to define how a runtime should intercept and govern a skill's actions, not just how to author a safe skill file, and it lands alongside the project crossing 30,000 members and adding four new sponsors — a sign of how fast agent and skill governance tooling is institutionalizing.

Sources: OWASP GenAI Security Project, Agent Control Standard resource page, PR Newswire, Forkast News

4. Claude Enterprise's "smart reports" beta mines team usage logs to recommend which workflows to turn into shared skills

Anthropic quietly shipped smart reports in beta for Claude Enterprise: a feature that scans a team's Claude, Claude Code and Cowork transcripts over up to a 28-day window and surfaces adoption, cost and — most notably here — "most common frictions" such as unset connectors, mismatched output, approval gating, tool failures and rework loops, alongside a list of repeated patterns worth packaging as shared skills, complete with a starter prompt to build them. Each org gets 10 free reports a month during the beta, scoped per functional team (sales, finance, engineering) rather than org-wide for a cleaner signal. It's a direct, enterprise-grade answer to the skill-quality and curation problem this digest has tracked since July: instead of hand-vetting a marketplace, an org's own usage data now surfaces which internal workflows deserve to become a maintained SKILL.md, closing the loop between Claude's usage analytics and its skill-authoring pipeline.

Sources: Claude Support

5. "Skill-as-API" proposes hiding a skill's actual logic from other agents during multi-agent coordination

A September 1, 2026 arXiv paper, "Skill-as-API: Confidential Multi-Agent Coordination for Agentic Software Engineering," tackles a gap current protocols like MCP and A2A leave open: they publish a skill's full description and typed schema to every peer agent, with no way to hide that a skill exists or keep its system prompt off the wire — which the authors argue leaks IP the moment coding agents start invoking each other's specialized skills. Their proposed protocol limits what's public to name, description, typed I/O schema and a trust tier, keeps skill bodies inside the owner's process, and adds trust-tier access control, auto-downgrading of "throwaway" trust, and a function-boundary defense that narrows the prompt-injection surface structurally. It's positioned as a protocol-layer complement to MCP/A2A rather than a replacement, validated via an open-source implementation and a pull-request-review case study — directly relevant to enterprises worried about proprietary skill logic leaking as skill marketplaces and inter-agent coordination scale up.

Sources: arXiv abstract, arXiv full text
