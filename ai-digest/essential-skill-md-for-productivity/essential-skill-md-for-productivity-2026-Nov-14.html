1. Claude Code 2.1.325 makes scheduled tasks ask before running skills that grant themselves tools

Claude Code 2.1.325 (13 November) changes how skills behave when nobody is watching. Scheduled tasks and /loop now ask before running a skill that declares allowed-tools or hooks. To keep an unattended routine running, add Skill(name) to permissions.allow so you approve that one skill once. The sandbox now refuses sandboxed writes to .claude settings, skills, agents, commands and hooks in added directories, as it already does in the launch folder, so a tool call can't quietly rewrite a skill. Nested skill loading changes too: .claude/skills folders inside --plugin-dir plugins no longer load from a session started above them. claude plugin validate now reports unsafe paths and links in a plugin's folder, and install and marketplace prompts now warn that plugins can run code with access to your files and shell. Other fixes: a managed strictPluginOnlyCustomization lock on skills now applies to sessions that are already running, and skills' inline git commands no longer fail in bare-repository and repo worktrees. If you schedule skill-driven routines, check your allow list after upgrading.

Sources: Claude Code v2.1.325 release (GitHub), Claude Code CHANGELOG

2. Codex 0.169 adds a migration for Claude Code skills and narrows its built-in docs skill

OpenAI's Codex 0.169.0 (13 November) adds a local-only migration for Claude Code skills (PR #60492, merged 10 November). A new claude-code-local-skills source imports skills from your Claude Code home folder but skips the synced folder, and .trash folders are always left out. If you use both agents, you no longer have to copy SKILL.md folders by hand or keep two copies. The bundled openai-docs skill now focuses on Codex and ChatGPT Work questions and first-time API setup, with new guidance on configuring Codex for a team. Read and installation tools now show a skill's display name. Typed punctuation after a skill mention is kept. Plugin starter prompts can be up to 512 characters, and marketplace upgrades reuse Git objects already on disk, which cuts repeat downloads. Codex 0.168.0, released the same day, lets model catalog overrides supply plugin guidance and packages the message-board MCP connection as a plugin.

Sources: Codex 0.169.0 release (GitHub), Codex PR #60492: Claude Code skill migration, Codex releases

3. Copilot CLI 1.0.111 and 1.0.112 make plugin status honest and skill search ignore hidden text

GitHub shipped two stable Copilot CLI releases on 13 November. In 1.0.111, search in /skills, /mcp and /plugin matches only visible text, not words hidden inside terminal escape sequences. That extends the picker fix in 1.0.110 to search, so a booby-trapped skill can't show up for a search it doesn't visibly match. Plugin hooks can now use ${COPILOT_PLUGIN_ROOT} in their working directories and environment values, so a plugin's hooks can find their own scripts wherever the plugin is installed. Plugin commands now fail, naming the file, when config.json can't be parsed, instead of reporting success. In 1.0.112, the /plugin manager no longer shows a repository plugin as enabled when it failed to load. Organization-required plugins are prepared once at startup instead of installing twice. /env no longer lists instruction files you disabled in /instructions as loaded. Taken together, the CLI's skill, plugin and instruction lists now match what is actually loaded.

Sources: Copilot CLI v1.0.112 release (GitHub), Copilot CLI v1.0.111 release (GitHub), Copilot CLI releases

4. OpenCode 2.3 returns skills as structured results in Code Mode and gives plugins a fork hook

OpenCode 2.3.0 (13 November) changes its skill tool in Code Mode, where the model writes code to call tools. The tool now returns a skill's directory and content as structured results instead of plain text. Code can then find a skill's bundled scripts and reference files without parsing prose, which matters for skills that ship more than a SKILL.md. Plugins get an experimental session.fork hook. @opencode/plugin/effect now exports Tool, so an execute.before hook can reject a call with a typed error. A failed cleanup no longer blocks a plugin from being replaced, and plugin-provided themes update live. Subagents now always run in the background: they return their session ID at once and report back when idle, so a parent agent working through a skill isn't blocked. The previous release, 2.2.7 (10 November), already kept Console workspace policies in force when Console's instructions or skills fail to load.

Sources: OpenCode v2.3.0 release (GitHub), OpenCode releases

5. Salesforce makes Skills generally available in Agentforce Coworker as usage passes 185,000 people

This item is older than the 24-hour window. Salesforce made AI Skills in Agentforce Coworker generally available. Its 4 November release schedule listed Skills as available now, Salesforce's blog announced it, and Salesforce Ben covered it on 12 November. A Coworker skill is a saved set of plain-language instructions for a repeatable task. Anyone can then run it with a short request, and it can be shared with colleagues. Skills stay private until shared and run with each user's own CRM permissions. They pause for approval before creating or updating a record. The launch came with a $50-per-user-per-month Coworker option, Google Workspace and Microsoft 365 connectivity, and conversation history. Daily digests and scheduled tasks are due in December. Salesforce says Coworker passed 185,000 users and that usage grew 21-fold in three months. Those are Salesforce's own adoption figures, not measured productivity gains. For non-developers, this is one of the largest CRM-side uses of the skill pattern: one person's tested routine becomes a single command the whole team can run.

Sources: Salesforce blog: AI Skills in Coworker, Salesforce: Agentforce Coworker surpasses 185K users, Salesforce Ben, Salesforce Asia press release, TechWyse
