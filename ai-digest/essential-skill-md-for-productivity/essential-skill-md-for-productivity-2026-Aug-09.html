1. Zenity Labs uncovers a 1.7M-install credential-theft campaign hiding in trojanized skills.sh listings

On August 6, Zenity Labs disclosed an active campaign on Vercel's skills.sh open agent-skills registry in which attackers cloned popular skills, let a typosquatted "Paperclip" skill family accumulate legitimate-looking install counts while still clean, and only then swapped in malicious instructions. Once weaponized, the poisoned skills directed AI agents to exfiltrate SSH keys, cloud and Kubernetes/Docker credentials, package-manager and Git tokens, environment files, and service-account secrets to attacker-controlled infrastructure — the affected family alone had racked up more than 1.7 million aggregate installs (not unique users) before discovery. Vercel and Microsoft/GitHub pulled the flagged skills, marketplace listings and repositories within roughly 12 hours of Zenity's disclosure, but researchers warn anyone who installed the skills earlier remains exposed until they manually remove them, since a registry takedown doesn't touch what's already on a machine. It's the largest confirmed real-world exploitation yet of the "accumulate trust, then poison" pattern this digest has tracked conceptually via SkillCloak (Aug 2) and Mitiga's leaked-key findings (Aug 7) — proof the technique is already running at scale against a mainstream, developer-trusted skill marketplace.

Sources: BusinessWire, TechRadar, CSO Online, The Next Web, VMblog

2. Claude Code v2.1.226 ships beta skill-and-plugin security scanning with pass/warn/fail verdicts

Anthropic's Claude Code v2.1.226, released August 8, adds a beta "skill and plugin security scanning" feature for Enterprise plans: every third-party skill or plugin — including skills bundled inside a plugin — is automatically reviewed the moment someone uploads or edits it, with scans typically finishing in one to two minutes. Claude returns one of three verdicts: pass (installs normally, no extra friction), warn (usable behind a caution banner the user must acknowledge, when the scan can't fully verify safety), or fail (blocked outright as detected malicious content). Organizations turn it on centrally under Organization settings → Skills, applying the check org-wide rather than per-user. Landing two days after the Zenity skills.sh disclosure above — and a day after this digest's Aug 8 edition flagged this exact feature as too unconfirmed to include — the timing underscores how install-time scanning is becoming a first line of defense against the trojanized-skill pattern, distinct from the inference-time DLP hooks Claude Enterprise shipped Aug 7, which vet live tool/skill responses rather than the skill file itself at install.

Sources: Claude Help Center, Claude Help Center — Use skills, Releasebot, Havoptic

3. Ponytail's maintainer corrects its own headline benchmark to match independent tests, passes 82K stars

Ponytail, the single-file SKILL.md this digest covered passing 74,000 GitHub stars on Aug 1 (citing independent third-party benchmarks that already measured a 54% code reduction), corrected its own official numbers this week to match, after a contributor challenged the project's original marketing claim of 80-94% less code — a figure InfoQ reports rested on a non-agentic baseline. Maintainer Dietrich Gebert rebuilt the benchmark as a real agentic run — twelve feature tasks against a live FastAPI/React repository through Claude Code — and landed on essentially the same ~54% average reduction independent testers had already found, reaching the original 80-94% figure only where an agent had been over-building, and near zero where code was already minimal, alongside roughly 20% lower cost and 27% faster execution. The public correction hasn't slowed adoption: the repository has now passed 82,000 GitHub stars, up from 74,000 just over a week ago. It's a useful case study in a viral SKILL.md project's own headline metric catching up to what independent community benchmarks had already been reporting, rather than the reverse.

Sources: InfoQ, GitHub — DietrichGebert/ponytail
