1. Skill-α trains agents to write their own skills, one evaluable edit at a time

A team from the Chinese University of Hong Kong, LIGHTSPEED, and an independent researcher published Skill-α, a reinforcement-learning method that grows a skill file the way a person iterates on a draft rather than generating it in one heuristic pass. It formulates skill construction as a sequential editing process and introduces a "rollback reward" that scores each edit by running the same anchored query through the pre- and post-edit skill and comparing downstream execution — giving skill generation a real supervision signal where previously a skill's quality could only be judged after the fact by whether it happened to help an agent finish a task. For teams building or automating a personal skill library, it's early evidence that skill authoring can move past templated boilerplate toward skills that are measurably better with each revision. The paper and a reference implementation, skill-alpha, went up on August 3.

Sources: arXiv:2608.01678, Full text (HTML), GitHub — skill-alpha

2. Microsoft's Copilot Studio GitHub Copilot harness — previewed 28 July — reaches general availability

The rebuilt Copilot Studio engine covered here on 28 July hit a concrete milestone this week: the GitHub Copilot harness that powers its most capable agents is now generally available for production use. It gives Copilot Studio agents the same coding and reasoning scaffolding behind GitHub's Copilot coding agent and Copilot Cowork, built for complex, long-horizon business processes on frontier reasoning models including Opus 5, GPT-5.6 Sol, and Fable 5. What makes it relevant here: the harness invokes reusable, developer-packaged skills built on the Agent Skills open format that Anthropic originally published, so a skill authored once can now run inside a production Microsoft agent rather than only Claude Code or GitHub Copilot. Microsoft frames it as cost discipline as much as capability — teams package business logic once as a skill and the system applies model compute only where it adds value — another sign the open Agent Skills spec is becoming real cross-vendor infrastructure rather than an Anthropic-only convention.

Sources: Microsoft Tech Community, Hubsite365

3. Crun AI open-sources a SKILL.md-compatible media-generation skill set

Crun AI released an open-source media-generation skill set on August 4, giving any SKILL.md-compatible agent — Claude Code, Codex, Cursor, or otherwise — pre-built skills for image, video, music, and speech generation without hand-rolling a prompt pipeline per model. The skill set routes requests across 138 models through Crun's API, including Seedance 2.5, GPT-Image 2, Nano Banana, Veo 3.1, Grok Imagine, and Seedream 5 Pro, so one skill invocation can estimate cost, generate, and retrieve creative output in a few lines instead of bespoke per-provider integration code. It's a useful marker of where "essential" productivity skills are heading beyond text and code: creative and multimodal workflows are getting the same one-file, install-and-invoke treatment coding skills got first. As with any third-party skill, it's worth running it through a scanner before trusting it with API credentials — this digest has tracked a steady run of vulnerable or malicious skills hiding behind a legitimate-looking README.

4. Black Hat USA 2026 reframes agent exploitation around framework logic, not just skill content

At Black Hat USA 2026 this week — 29% of the conference's 121 briefings now cover AI security, formalizing agent exploitation as its own discipline — Check Point Research presented "No Tools Required: Post-Injection Exploitation Across AI Agent Frameworks," arguing the real attack surface isn't the tools a skill or agent can call but the framework's own decision-making logic. Their techniques include delayed-execution injection that triggers across later conversation turns, cross-agent propagation in multi-agent setups, and persistent memory poisoning, and they report exploitable logic in the core runtimes of LangChain, CrewAI, AutoGen, and Semantic Kernel — memory stores, planning loops, and serialization layers, not just skill files or tool permissions. That reframing matters directly for skill security: this digest has tracked a string of skill-file scanners (SkillSpector, defenses against SkillCloak-style evasion, and others), but Check Point's point is that hardening skill content alone still leaves the runtime that interprets it exposed. A related NVIDIA talk follows on August 6 showing a fine-tuned open model can exploit agents at a fraction of frontier-model cost, underscoring that this class of exploitation is becoming cheap enough to run at scale.

Sources: Forkast News, Straiker

5. Google adds Agent Skills Lifecycle Governance to Gemini Enterprise, targeting context poisoning and supply-chain exploits

Google Cloud shipped Agent Skills Lifecycle Governance for its Gemini Enterprise Agent Platform, adding semantic governance policies that control which skill packages an agent may dynamically load during a session — a direct answer to the context-poisoning and supply-chain patterns this digest has covered repeatedly, from the 26,000-agent Instagram skill hijack to SkillCloak-style scanner evasion. Because loading a skill happens through an ordinary tool call, Google can apply the same semantic governance policies it uses elsewhere on the platform to the entire skill lifecycle, restricting which skills load under specific conditions and blocking untrusted data — like a malicious email an agent reads mid-session — from subverting the user's original intent. It's a narrower, more mechanical answer than a pre-install scanner: rather than scoring a skill's risk before install, it constrains what a skill can do at runtime regardless of what static analysis missed. Documentation for the feature dates to late July, so it's included here as a slightly older but still-current item given how squarely it targets this digest's recurring skill-security thread.

Sources: Google Cloud Docs, Release notes
