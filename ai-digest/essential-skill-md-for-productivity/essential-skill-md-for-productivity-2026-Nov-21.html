1. Claude Code 2.1.330 stops a skill's model setting spreading into subagents, and lets scheduled loops run for 30 days

Claude Code 2.1.330 reached npm at 19:16 UTC on 20 Nov. The skill change that matters most: when a skill sets its own model, that model no longer carries over to subagents, forks, compaction or /recap, which all stay on the session's model. context: fork skills work as before. That keeps a skill pinned to a cheap or fast model from quietly downgrading everything it starts. /rewind no longer restores an older copy of a file when two stacked skills or queued prompts ran right after a turn that changed it. Code Mode no longer drops earlier thinking and rebuilds the prompt cache when a mod adds a note after a script loads a skill. claude plugin install --json now reports commandPrinted and commandFailed, so install scripts can tell when a plugin's own setup step failed. Recurring scheduled tasks and /loop can now run for up to 30 days instead of 7 while their session stays open, and prompt hooks accept model aliases such as haiku.

Sources: Claude Code CHANGELOG (2.1.330), Claude Code changelog, npm: @anthropic-ai/claude-code

2. Google adds a 2,450-line Pub/Sub decoupling skill and a Google Health plugin that installs in five agents

Google's public skills repo had eight commits on 20 Nov. The largest, google-cloud-solution-event-driven-decoupling, has a short SKILL.md router and seven reference files, 2,450 lines in all. It takes an agent from assessing coupling, through an outbox-first Pub/Sub design, to consumer autoscaling and distributed tracing. The agent must pass a Phase 1 gate before it builds anything, and the skill sets a database connection budget, least-privilege IAM rules and cleanup rules for test resources. It can also run one phase on its own for a narrower request. The skill gives table-of-contents line ranges for its long reference files, so the agent can read only the section it needs. The same day, Google added a google-health-developer plugin. Its one set of files carries manifests for Claude Code, Codex, Gemini CLI, Antigravity and generic MCP clients, and points them at a read-only docs MCP server that needs no API key. Its AGENTS.md tells agents to search the docs before writing code and to cite a link for each page they use. The other commits link the API Gateway skills together, fix facts that disagreed with API Gateway behaviour, and correct stale schema rules in gke-compute-classes.

Sources: google/skills commit bf80eb9 (event-driven decoupling), google/skills commit 59ab873 (Google Health Developer plugin), google/skills commit 613a392 (API Gateway skills), google/skills commit ee54bb3 (gke-compute-classes v1.0.2), google/skills commit log

3. Qwen Code preview gives every new workspace session a set of default skills, pinned to exact revisions

Qwen Code 0.28.1-preview.1 reached npm at 20:11 UTC on 20 Nov. It is the first preview to include PR #17703, merged on 18 Nov, which changes how its managed agent service starts workspace sessions. A host app can now publish a catalog of default skills for each tenant, user and workspace. A new session with no skills chosen gets that default set, each pinned to an exact revision, so its instructions can't change underneath it. An older session keeps the revisions it started with, even after the defaults change. An explicit pin list picks different skills, and an empty list turns the defaults off. The PR also fixes a gap where an imported skill could run but was missing from the session's slash-command menu. Catalogs are capped at 256 skills and 2 MiB, and a skill with blank instructions is rejected before the session starts.

Sources: PR #17703: discover and pin default workspace skills, Qwen Code releases (0.28.1-preview.1), npm: @qwen-code/qwen-code

4. Copilot CLI 1.0.115-2 keeps a rewound skill gone after compaction, and says why a plugin installed no skills

GitHub published Copilot CLI 1.0.115-2 at 14:33 UTC on 20 Nov, with 1.0.115-3 following that evening. If you rewind a turn that invoked a skill, that skill's instructions now stay removed through compaction and session resume, instead of quietly coming back into context. copilot plugin install and /plugin install now explain why a plugin's Agent Plugins manifest was rejected. Before, they could report skills as installed even when the plugin loaded nothing. Paths with repeated spaces now work in /skills add and /skills remove, and plugins install from repository paths containing @, such as scoped package folders. A turn also no longer waits for background agents' pending updates before it ends. These are pre-release builds; the current stable release is 1.0.114.

Sources: Copilot CLI releases (1.0.115-2, 1.0.115-3), Copilot CLI changelog, npm: @github/copilot

5. A community pack of about 70 skills adds a skill-critique command that measures what your installed skills cost per session

The mmgordon82/agent-skills project tagged release 20261120 at 15:56 on 20 Nov. It installs with npx skills add mmgordon82/agent-skills#20261120 -g --skill '*', or from a tarball into ~/.agents/skills. For people with a lot of skills installed, the most useful addition is /skill-critique. It lists every installed skill, estimates how much each adds to every session's context, and flags skills whose triggers overlap. It changes nothing until you approve. Other skills give an agent firmer habits: adversarial-review has a different agent CLI check finished work, read-only. run-validation picks the lightest environment that can actually prove a test or deploy works. handoff writes a checked record with secrets removed for the next session. benchmark-checklist requires at least five alternating runs, reported as median and range, before any speed claim. Around 30 more short "engineering principle" skills, such as fix-root-causes and guard-the-context-window, load only when you call them by name.

Sources: mmgordon82/agent-skills release 20261120, mmgordon82/agent-skills repository
