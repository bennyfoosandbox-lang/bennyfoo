1. Perplexity's Brain now writes and updates personal skills for you, on by default for US Max subscribers

Perplexity has extended Brain, the memory system behind its Computer agent, so it creates and refines reusable skills from your past sessions instead of waiting for you to write them. It also updates the built-in skills every user gets, based on patterns across all sessions. Brain proposes changes rather than editing skills directly: automatic checks confirm each proposal is well formed, a separate AI judge reviews a sample, and each user is capped at 10 auto-created skills, so adding another means retiring one and justifying the swap. Perplexity reports more than 80,000 personal skills written for over 20,000 users between 1 Aug and 14 Nov. In an eight-week randomized test, 72.9% of users with the feature on got at least one new skill, against 6.5% of controls who added one by hand. The feature is on by default and can be turned off. Sources disagree on who gets it: the blog says US Max subscribers, Perplexity's X post says all US consumer and enterprise subscribers. This item is from 18–19 Nov, used because the last 24 hours had too few new items.

Sources: Perplexity blog, Perplexity on X, Unite.AI, FourWeekMBA

2. Google cuts its four API Gateway skills by 176 lines and replaces a multi-step lockdown with one command

On 21 Nov, Google's public skills repo made one commit, 4bb21eb, which reworks the four API Gateway skills linked together the day before: backend security and rate limiting, MCP server, OpenAPI spec authoring, and troubleshooting. Across 18 files it adds 224 lines and removes 400. The biggest change is in backend security. The old procedure asked the agent to strip public access bindings one by one. It is now a single gcloud run services update --no-allow-unauthenticated, run only after the gateway is serving the new config. The client authentication guide now says API keys are read from the x-api-key header first, with the query parameter as a fallback, and warns against using an empty security entry to make OAuth2 or JWT optional. It is a good example of a skill getting shorter and more accurate, which means less context spent each time it loads.

Sources: google/skills commit 4bb21eb, google/skills commit history

3. Qwen Code 0.28.3 brings default workspace skills to the stable release, and lets mixed packages load in content-only runtimes

Qwen Code 0.28.3 reached npm at 02:07 UTC on 21 Nov. It moves the default workspace skills from last week's preview into the stable channel: a new workspace session created without its own skill list gets a default set from an optional catalog, each pinned to an exact revision (#17703). The release also includes #17944. Some runtimes can't start processes, and before this change a package that bundled a skill with a hook or MCP server was rejected outright there. Now the skill, commands, agents and context load as normal, the hook and MCP server stay inactive, and each package reports a degradedComponents list so you can see what was skipped. A nightly the same evening (0.28.3-nightly.20261121) fixes extension manifests that were saved with a UTF-8 byte-order mark and failed to load (#15786).

Sources: Qwen Code releases, PR #17944, PR #17703, npm @qwen-code/qwen-code

4. Anthropic's code-modernization plugin now looks up supported versions instead of guessing them

PR #7170 to Anthropic's official plugin directory, merged on 20 Nov, moves the code-modernization plugin to 1.1.0. It fixes a familiar problem: in the PR's own tests on a small legacy app, two runs suggested different upgrade targets because the model relied on memory instead of checking. Any command that proposes, confirms or builds for a target language or framework version now follows a shared rule in references/target-versions.md. That rule looks up current support and records each version in a Target versions table with its end-of-support date, source and the date it was checked. A version the user names is kept, with a warning and a supported alternative if its support has ended. If every lookup fails, the row is marked unverified and a person has to pin the version before the build. The review agent, architecture-critic, is deliberately given no web tools. It only judges the table that was recorded.

Sources: PR #7170, commit d7d3279, claude-plugins-official commits

5. Copilot CLI 1.0.115-4 and -6 fix a plugin startup race and retry org-required plugin installs straight away

GitHub published three Copilot CLI pre-releases on 21 Nov. 1.0.115-4 (01:53 UTC) fixes a race during plugin initialization that could block new sessions or stop existing ones from resuming. 1.0.115-6 (20:57 UTC) changes how plugins your organization requires are installed: if a temporary policy change interrupts setup, the next attempt can install them without waiting for the usual retry delay. For teams that send skills through required plugins, both fixes mean fewer sessions starting without the skills they expect. 1.0.115-5 in between had no plugin or skill changes. None of the three changes how skills or instructions themselves are handled.

Sources: Copilot CLI releases, npm @github/copilot
