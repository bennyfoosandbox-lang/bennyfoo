1. Uber says agents now complete over 70% of its merge requests — powered by 3,600 hand-written agent skills

Uber's engineering blog, in a post titled "Running a Software Factory Efficiently at Uber Scale," disclosed that more than 70% of the company's code merge requests are now attributed to local or cloud coding agents, with engineers having authored over 3,600 agent skills spanning the software development lifecycle that together execute more than 30,000 times a day. Weekly active users of Uber's agentic tooling grew sevenfold and weekly agent requests grew 9.4x between February and August 2026, yet total AI spend has stayed flat since April — the post credits a unified model gateway (identity checks, PII redaction, and routing across every model call) and a skill market that lets reusable processes be looked up instead of re-derived by every agent. A code-review agent, uReview, posts roughly 25,000 comments a week with about two-thirds acted on, cutting review costs about 60% versus Uber's first implementation, and average lines of code shipped per engineer have roughly doubled year over year. It's one of the most concrete public data points yet that a large internal skill library, not just a bigger model, is what turns agent adoption into flat-cost throughput.

Sources: Uber Engineering blog, CellCog analysis

2. AWS Agent Registry reaches general availability — a governed, searchable catalog for agents, MCP servers, and skills

Amazon Web Services made AWS Agent Registry generally available on August 31, through Amazon Bedrock AgentCore, giving organizations a fully managed, searchable catalog where teams publish MCP servers, agents, agent skills, and custom resources behind an approval workflow. The registry separates a Governance Plane, which stores every record and the policies admins configure for it, from a Discovery Plane that exposes only approved records to consumers, and accepts four record types — including Skill records that hold markdown skill definitions with their associated code or packages. An auto-detection feature targets shadow AI directly: enabling endpoint detection at the AWS Organizations level surfaces agents and MCP servers already running on AgentCore Runtime and Gateway across accounts as draft records that flow into the standard review process. Consumers can query the catalog through a Search API exposed as an MCP server, and Kiro and Claude Code can connect to a registry instance natively via Dynamic Client Registration, letting a developer find an approved skill in natural language from inside the editor. AWS cited Southwest Airlines, Syngenta, Sony, Mitsubishi Electric, PepsiCo, and Amdocs as early users, with a monthly free tier covering the first 5,000 records and 1,000,000 search calls before consumption pricing kicks in.

Sources: Unite.AI, AWS Machine Learning Blog

3. Poisoned SKILL.md files emerge as a persistence trick in a wave of Claude credential-theft campaigns

Security researchers disclosed on August 31 that Anthropic is fighting two separate campaigns to hijack Claude accounts. The first uses infostealer malware — Vidar, Lumma/LummaC2, StealC, RedLine, and Acreed on Windows, plus Atomic Stealer on macOS — that harvests browser session cookies well enough to bypass passwords, MFA, and SSO, letting an attacker ride a victim's authenticated Claude session and burn through their subscription undetected. A second campaign, tracked by Huntress as FakeAgent, used sponsored Bing results for the Claude desktop app to route victims to a trojanized ClaudeDesktop.exe hosted on the legitimate claude.ai domain, which DLL-sideloaded the SectopRAT remote-access trojan and compromised at least 29 organizations in two days before Anthropic pulled the artifact, by which point it had roughly 7,100 downloads. Most relevant for skill-based workflows, researchers warn that poisoned SKILL.md files — disguised as ordinary style-guide notes — can act as a reinfection mechanism: if a tainted skill file survives a clean OS reinstall and gets loaded again, hidden instructions can silently re-download the infostealer. Anthropic is invalidating compromised sessions and refunding fraudulent charges but says it can't fully disinfect a device still running the malware, and researchers are telling teams to audit SKILL.md files for hidden instructions and sandbox agent workloads, not just rotate passwords.

Sources: GBHackers, Cyber Security News, PYMNTS

4. Anthropic extends Claude Code's Compliance API to local sessions — but coverage gaps remain

An August 31 analysis of Anthropic's Compliance API lays out how Claude Code's governance story has shifted since Anthropic added local-session transcript endpoints on August 11: for the first time, security teams can pull activity feed events, chat data, and file content from Claude Code sessions running on developer endpoints, not just cloud-hosted usage, through the same API that already integrates with CrowdStrike, Microsoft Purview, Okta, Wiz, and Zscaler. The piece, together with a companion write-up from identity-governance vendor Token Security about folding Claude's Compliance API into its own identity control plane, frames this as closing a real blind spot: before August there was no centralized way to see what a locally running Claude Code agent — with its own skills, hooks, and permissions — was actually doing. Both are careful to flag what's still missing, though: the new endpoints capture Anthropic-model activity surfaced through Claude Code itself, but still miss locally configured hooks, arbitrary shell commands a skill triggers outside the transcript, and any activity from non-Anthropic models a developer might be routing through the same agent. For teams running SKILL.md-driven Claude Code deployments at scale, it's progress on visibility, not yet full governance.

Sources: The Hacker News, Anthropic Help Center, Token Security

5. Researchers warn shadow AI is now hiding inside the very tools security teams already approved

A Hacker News expert-insights piece published August 31 argues that the shadow-AI problem enterprises spent the last year trying to inventory — unsanctioned copilots and browser extensions — has moved inside tools that were already approved. The researchers cited found malicious AI Skills, MCP servers, editor plugins, and repository configuration files capable of stealing credentials, exfiltrating data, or executing code, all installed through the normal extension or skill-marketplace flow of a sanctioned coding assistant rather than through some rogue app IT never signed off on. Because a SKILL.md file can carry both natural-language instructions and pointers to executable scripts, and a plugin can silently expand an agent's toolset after initial approval, the piece argues governance has to move from a one-time "is this tool allowed" decision to continuous visibility into what installed skills, plugins, and MCP connections are actually doing at runtime. The argument lands the same day as AWS's new Agent Registry auto-detection feature and Anthropic's own push to extend Claude Code's compliance visibility to local sessions — both covered elsewhere in this digest — suggesting shadow-skill visibility is becoming this week's shared industry concern rather than one vendor's talking point.

Sources: The Hacker News: Expert Insights
