1. Claude Code changes how nested .claude/skills folders load

A Claude Code release first logged on 7 November changes skill discovery in monorepos: skills stored in nested .claude/skills folders now load only when Claude Code is started inside that folder, instead of being picked up from wherever the session happens to run. The same release fixes a skill hot-reload bug, so edits to a SKILL.md should take effect without a restart. For anyone keeping a large library of productivity skills in a shared repo, this is a practical shift: skills scoped to a sub-project stop competing for context in unrelated sessions, but a skill you expected to see globally may now seem to vanish until you launch from its directory. The specific version number was not visible in the release aggregator snippet, so check the official changelog before pinning anything to it.

Sources: Releasebot: Anthropic updates, Releasebot: Claude updates

2. LaunchDarkly lets teams version SKILL.md files like feature flags

LaunchDarkly's AgentControl now manages agent skills as single versioned SKILL.md documents, YAML front matter plus a Markdown body, that can be attached to a config variation without shipping code. The feature was announced in beta on the Python and Node.js AI SDKs in early October and a later changelog entry marks it out of beta, requiring launchdarkly-ai-server 1.0.0 or later (Python 3.12+) or @launchdarkly/ai-node 1.0.0 or later (Node 22+). The pitch is operational: instruction files for agents get the same rollout, targeting and rollback controls as any other runtime config, and filesystem-based agents such as the Claude Agent SDK can read the skill files from disk. It is a rare example of the SKILL.md format being borrowed by a feature-management vendor rather than a coding-agent maker. This item is from slightly outside the 24-hour window because nothing newer passed deduplication; the exact GA date was not shown in the sources.

Sources: LaunchDarkly changelog: manage agent skills in AgentControl, LaunchDarkly docs: Agent skills, LaunchDarkly docs: Agent skills in the SDK

3. .NET teams start shipping SKILL.md files inside NuGet packages

A cluster of .NET tooling now treats agent skills as versioned package contents. The AgentSkills.Sdk NuGet package lets library authors ship agentskills.io-compliant skills inside their own package, ChilliCream's dnx-run skills CLI installs and updates skills with a single canonical copy symlinked to every agent, and another tool reads local .csproj files to install only the skills matching the NuGet packages a project uses. A write-up on the trend highlights the trade-offs: the three-level loading model keeps idle skills cheap, but token costs, stale copies and trust remain real risks, and one vendor catalog cites a 387,424-token total for its full set. For productivity, the takeaway is that skills for a library can now travel and update with the library itself. Most details come from vendor and community pages rather than Microsoft, and the sources were undated, so treat figures as approximate.

Sources: Windows Forum: AI agent skills in NuGet packages, ChilliCream: Skills CLI for .NET, NuGet: AgentSkills.Sdk

4. OpenCode Skills directory reaches 490 free skills

The opencodeskills.dev marketplace for OpenCode users listed 490 free skills when it was updated on 5 November, including 40 added in the previous 30 days. That is a modest pace compared with the big registries, but it shows the SKILL.md format spreading to smaller coding agents beyond Claude Code and Codex. OpenCode discovers skills from project and global folders and also reads .claude/skills and .agents/skills, so many Claude-style skills should work there without changes. Counts for competing catalogs vary widely, from a few thousand to tens of thousands, so the number mainly signals steady growth rather than a clear ranking. This was the thinnest item of the run, so verify the catalog yourself before relying on it.
