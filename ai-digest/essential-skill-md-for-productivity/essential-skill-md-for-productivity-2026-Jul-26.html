1. Copilot in SharePoint ships a native reusable-Skills system

Microsoft's July 2026 wave of Copilot in SharePoint updates adds a first-party, reusable Skills system: anyone with edit permissions on a site can type /Skills to see every skill available in that context, or simply describe a repeatable process — reviewing offer letters, triaging a compliance document — and have Copilot turn it into a multi-step Skill. Each one is stored as a Markdown file at /Agent Assets/Skills/<skill-name>/SKILL.md, a SharePoint-native instance of the same folder-plus-SKILL.md pattern that's become the industry default. Skills here are deliberately sandboxed — no external API calls, no custom code — with Copilot Studio positioned as the escape hatch for anything bigger. The rollout follows Copilot in SharePoint going on-by-default for every Microsoft 365 Copilot license on 16 June, and is described internally as one of the biggest single updates the product has shipped, bringing SKILL.md-style reusability to a surface used by hundreds of millions of knowledge workers.

Sources: Microsoft Tech Community, CloudFuze, WinCentral

2. Perplexity adds composable Skills to its Agent API

Perplexity shipped a Skills system for its Agent API in mid-July, letting developers assemble an agent from several discrete capabilities instead of one sprawling system prompt — pairing a built-in office/PDF skill with a custom formatting skill, for instance, to produce a finished, branded PDF research report in a single call. Perplexity frames Skills as curated, modular building blocks: general-purpose utilities for its Perplexity Computer product alongside vertical modules for finance, law, and health, with a fuller Skills Directory promised soon. The company had already published its internal manual on designing and maintaining agent skills, arguing that concrete worked examples beat exhaustive rule lists — the same lesson this digest has seen echoed across Claude, Codex, and GitHub Copilot's own skill-authoring guidance. The launch puts Perplexity alongside Anthropic, OpenAI, Microsoft, and Google in treating composable, first-party skills as the default way to extend an agent platform, rather than a bolt-on feature.

Sources: Perplexity API Platform Forum, Perplexity API Docs, @perplexitydevs

3. Microsoft's SkillOpt trains SKILL.md files like neural-network weights

Microsoft Research open-sourced SkillOpt, a text-space optimizer that treats a SKILL.md file as the trainable state of an otherwise-frozen LLM agent — applying epochs, batch sizes, learning rates, and validation gates to a natural-language skill document the way gradient descent trains model weights. A separate optimizer model reviews scored agent rollouts and proposes bounded add/delete/replace edits; an edit only survives if it strictly improves a held-out validation score, producing a versioned best_skill.md artifact rather than an ad hoc hand-edit. Version 0.2.0, released 2 July, added SkillOpt-Sleep — a nightly job that mines a coding agent's real session transcripts for recurring tasks, replays them offline, and folds the results back into long-term skills without any human curating the diff. It's a direct answer to the "skill smell" and skill-bloat problems this digest has tracked all month: instead of authors manually pruning bloated instructions, the skill improves itself from usage data, and open feature-request issues on unrelated agent projects already show developers asking to bolt SkillOpt onto their own stacks.

Sources: Microsoft Research, GitHub — microsoft/SkillOpt, SkillOpt project site

4. "Skills Are Not Islands" maps supply-chain risk across 1.43 million agent skills

A new paper argues that as agent skills mature, they've quietly become dependency-bearing software artifacts — with implicit, unversioned, largely unaudited links to other skills, packages, and external services — and that no one has measured that risk at scale. The authors built SkillDepAnalyzer to extract natural-language dependency evidence from skill documents, then applied it to 1.43 million skills, the largest such analysis published so far, to map what they call Agent Skill Supply Chains (ASSCs). The results show duplicated dependencies and inconsistent installations are already widespread, meaning a single popular skill's failure or compromise can propagate silently through everything that depends on it — a distinct risk from the prompt-injection and malware findings raised by earlier audits like ToxicSkills and SkillCorpus. For anyone assembling the "essential skill set" this digest has tracked converging around 8–12 skills, it's a reminder that governing skills as software means auditing their dependency graphs, not just scanning each file in isolation.

Sources: arXiv abstract, arXiv PDF

5. Salesforce's Agent Skills library learns to scaffold native mobile apps

Salesforce's curated Agent Skills library — the SKILL.md collection developers install to accelerate Agentforce Vibes coding — added generally available Mobile Skills that generate a production-quality native mobile app, authentication, offline support, and the Mobile SDK included, from a single prompt. The skills live in Salesforce's open sf-skills/afv-library repository, are tuned for Agentforce Vibes but work with any SKILL.md-compatible agent, and are being actively expanded toward more frameworks and richer end-to-end app-generation flows. It's a concrete instance of the pattern this digest keeps finding across ecosystems: rather than one skill that does everything, vendors are shipping narrow, one-job skills — mobile scaffolding, testing, deployment — designed to compose, echoing the same lean-SKILL.md authoring philosophy behind Claude Code's and GitHub Copilot's own bundled skills.

Sources: Salesforce Developers Blog, GitHub — forcedotcom/sf-skills
