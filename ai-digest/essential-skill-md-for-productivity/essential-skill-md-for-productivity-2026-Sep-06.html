1. GitSpawn: a booby-trapped repo can run attacker code in seven AI coding agents before you type a prompt

Manifold Security disclosed eight vulnerabilities across seven command-line coding agents — Claude Code, OpenAI Codex, Cursor, Goose, Hermes Agent, Qwen Code and Grok Build — all rooted in the same design flaw. Nearly every agent quietly runs context-gathering git commands like git status or git diff at session startup, and Git reads the core.fsmonitor setting for that operation from the repository's own untrusted .git/config. A malicious repository can point that setting at an arbitrary command, so simply opening the folder in an AI coding agent executes attacker code with the full privileges of the logged-in user — no prompt typed, no approval clicked, and outside whatever permission system the agent implements. Claude Code (confirmed vulnerable in v2.1.193, fixed in v2.1.196) and Goose (patched in v1.44.0 after CVE-2026-72718, CVSS 7.0) have shipped fixes, but Hermes Agent, Qwen Code and Grok Build remained exploitable as of publication on September 1. For a workflow built on "open a repo, let the agent get to work," it's a reminder that the trust boundary starts before the agent reads a single SKILL.md — it starts at git init.

Sources: The Hacker News, Manifold Security, GBHackers, Cybersecurity News

2. "A Finger on the Scale" shows a skill can pass every output check while covertly steering an agent's decisions

A new arXiv paper formalizes "Skill Policy Integrity": the idea that a reusable agent skill is really an externalized behavioral policy, and that policy can be hijacked while the skill still declares the same task and produces outputs that pass every format check. The authors build SkillShift, a constrained black-box framework that edits a skill's instructions just enough to redirect an agent's decisions toward an attacker's undisclosed objective — without injecting an explicit command or hijacking the stated task — combining semantically plausible edits with hierarchical validation and failure-guided optimization to keep the tampering both effective and inconspicuous. That's a sharper threat model than most skill-security coverage this year, which has focused on credential theft: here the payload is silent policy drift, not data exfiltration. For anyone building a productivity practice around installing other people's skills, it means "does it do what it says" is no longer a sufficient review.

Sources: arXiv:2609.02564, Full text

3. A skill that lifts your average score can still be sabotaging the exact task it was retrieved for

Researchers argue the standard way of testing "does skill retrieval help" is broken: comparing tasks where a skill was retrieved against tasks where it wasn't introduces selection bias, since the two task sets aren't equally hard. Their fix, Skill Following, uses a matched-pair metric — the Retrieval-Invoked Actual-Use Effect (RAE) — that measures the same-task outcome difference between running with and without the retrieved skill, restricted to only the tasks where the agent actually pulled one in. Testing 17 LLMs on coding and math benchmarks (including MBPP+), they find a stark "evaluation paradox": several models that look like they benefit from skills in aggregate score worse, on the exact tasks where a skill was retrieved, than they would have with no skill at all. For a topic built around "essential skills for productivity," it's a caution that a skill library's headline lift number can hide the fact it's dragging down the very tasks it fires on.

Sources: arXiv:2609.00549, Full text

4. SkillDreamer has the agent imagine the skill it wishes existed, then searches for that instead of the raw request

The paper names a specific failure mode it calls "Query-Skill Misalignment": task requests are phrased around goals ("get this dataset cleaned"), while skill libraries are written around procedures ("steps to normalize columns"), and that mismatch causes retrieval to miss skills that should have matched. SkillDreamer borrows from human "prospective cognition" — before searching, it infers what capability the task actually needs, generates a short pseudo-skill describing how that capability would be exercised, and uses that imagined procedure, rather than the raw query, to search the real skill library. Across multiple retrieval backbones and end-to-end task runs, the authors report consistent gains over matching the query directly to skill descriptions, and say the approach generalizes across different retrieval pipelines. It's a targeted fix for the everyday productivity failure of "the right skill existed in the library — the agent just never found it."

Sources: arXiv:2609.01642, Full text

5. SPACE teaches long-running agents when to stop second-guessing themselves, cutting wasted planning rounds

Most agent harnesses issue one action per LLM call so the agent can replan constantly — safe, but wasteful on long, routine jobs where nothing has changed since the last three steps. SPACE instead trains agents to emit variable-length chunks of actions, but the authors show naive reinforcement learning on this setup fails outright: the agent either collapses back to single-step behavior or over-commits to chunks so long it can't correct mistakes, because nothing teaches it where a chunk should end. Their fix distills chunk-boundary supervision directly from successful trajectories that have already been decomposed into two-level programmatic skills, using each subskill's natural boundary as the training signal for when to pause and reassess. It's a concrete mechanism for a common productivity ask — fewer, cheaper LLM round-trips on long-horizon work — without the accuracy cliff that cruder "just take bigger steps" approaches hit.

Sources: arXiv:2609.02042, Full text
