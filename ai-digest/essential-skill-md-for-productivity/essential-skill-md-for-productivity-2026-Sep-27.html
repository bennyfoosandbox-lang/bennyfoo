1. A new benchmark finds agents overclaim "done" on skill specifications by up to 38 points

"Who Holds the Pen? Let Specifications, Not Agents, Sign Off" names a structural problem with how most skills are checked today: the same model that executes a task also declares it finished, so a skill's written requirements never face an independent judge. The authors distinguish two failure modes — an understanding-execution gap, where a requirement is understood but not actually satisfied, and a state-authority gap, where the agent's own completion claim doesn't establish the state the skill demanded. Running SpecHarness against SkillsBench, they extracted 509 source-grounded task directions from agent-visible prompts, workspace state and injected skill specifications, then tested seven models: only 79.6–86.4% of directions were actually satisfied, while each model's self-reported completion rate exceeded the official evaluator's pass rate by 28.7–37.9 percentage points. For anyone treating a SKILL.md's "done" signal as trustworthy, that gap is the number to remember — the fix the authors argue for is letting the specification itself sign off, not the agent that wrote to it.

Sources: arXiv:2609.29921, Full text (HTML), redreamality.com analysis

2. SkillPivot finds the exact sentence where a skill run went wrong, instead of rewriting the whole thing

"A Wrong Turn Does Not Ruin the Journey: Deviation-Guided Skill Self-Evolution for LLM Agents" tackles a specific, common mistake in how teams iterate on their own skills: treating every failed run as entirely wrong and revising the skill to force future attempts down one fixed successful path. The authors point out that most failures aren't like that — an agent often gathers real evidence and makes genuine progress before deviating into an erroneous suffix, so forcing a single template throws away everything it got right. Their framework, SkillPivot, instead detects the deviation point — the transition from a useful prefix to a broken suffix — using execution validity, goal progress and action diversity as signals, then revises the skill only around that pivot rather than the whole trajectory. It's a more surgical model for skill maintenance than most teams currently practice: keep what worked, patch only where it broke.

Sources: arXiv:2609.29154, Full text (HTML)

3. Docker ships an open, cross-agent skills collection for containerized development

Docker published docker/skills, an open GitHub collection of Docker-authored SKILL.md directories that teach coding agents to build, test, debug and optimize containerized apps with consistent, reusable workflows instead of ad hoc container commands. The set includes narrowly scoped skills like docker-agent-config (authoring agent.yaml for Docker Agent/cagent — agents, models, providers, toolsets, multi-agent teams), docker-agent-run (safety/approval modes, sandbox isolation, worktrees) and docker-agent-deploy (exposing agents as servers via OCI registries and regression-checking them in CI). Because they're plain portable SKILL.md folders, a bundled CLI installs the same skills into Claude Code, Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, Windsurf, Cline and Kiro rather than locking the workflow to one vendor's agent. For a digest built around "essential" skill packs, this is a concrete, first-party one worth adding to a starter set for anyone doing container-heavy development.

Sources: github.com/docker/skills, Docker Docs — Skills

4. Microsoft Agent Framework 1.19.0 makes skill archives ZIP-only and requires a SHA-256 digest match

Microsoft tagged Agent Framework 1.19.0 for both the .NET and Python packages on September 18, and the headline change for anyone distributing skills as archives is integrity verification: skill archives must now be plain ZIP files, and when an archive entry supplies a digest it has to be sha256: followed by 64 lowercase hex characters, which the framework checks against the decoded archive bytes before extraction. An invalid or mismatched digest quietly skips that one archive rather than blocking every other skill in the set, while an omitted digest is still allowed — so the check is additive, not a hard requirement that breaks existing unsigned skills overnight. The same release scopes MCP sessions per invocation and authenticates requests against the correct invocation identity, origin and ownership, closing off a class of cross-session confusion bugs. It's a small but concrete step toward treating a skill archive like any other software dependency: verify what you're extracting before you run it.

Sources: GitHub release — Python 1.19.0, GitHub release — .NET 1.19.0, juliangoldie.com summary

5. GitHub Copilot's "September Reset" lands this week: unified agent experience, prepaid seats, Balanced reviews by default

Several of the Copilot billing and policy changes GitHub previewed on August 28 take effect around this digest's publish date. The most visible is a unified agent experience — merging Copilot Cloud Agent, the chat on github.com and GitHub Mobile Chat into one interface — rolling out no earlier than September 28, alongside a change that keeps chat history for the lifetime of the account instead of deleting it after 28 days. Separately, new Copilot Business and Enterprise seat assignments have required prepayment since September 1 (existing customers follow October 1), promotional AI credits are shrinking (Business from 3,000 to 1,900 per user/month, Enterprise from 7,000 to 3,900), and the default code-review effort level is moving from Lite to the more thorough Balanced. None of this is a skills-format change, but Copilot remains the most widely deployed agent-skill-compatible coding assistant in most orgs, so a shift in its default review depth and where agent chat lives changes how teams actually reach for shared skills day to day.

Sources: Developers Digest, GitHub Changelog, DevOps.com
