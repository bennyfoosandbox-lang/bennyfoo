1. Claude Code 2.1.318 makes the claude-api onboarding skill default to auto-approval and hardens how commands and connectors behave

Claude Code 2.1.318 shipped on 4 November. The skills-relevant change is that the bundled /claude-api managed-agents-onboard flow now gives a new agent's built-in tools, and a quickstart template's MCP tools, the auto permission policy ("Judge risky actions") by default, with a "run without asking" opt-out. The release also fixes custom slash commands that fail, or that only Claude can invoke, printing nothing in claude -p and SDK sessions, which matters for anyone scripting skills headlessly. deniedMcpServers URL entries now also block Anthropic-provided servers and cloud-session connectors, tightening the guard rails around skills that lean on MCP.

Sources: Claude Code v2.1.318 release notes, Claude Code releases

2. Superpowers v7.0.2 makes brainstorming ask fewer questions and fixes skill bootstrapping on six harnesses

The obra/superpowers skill collection released v7.0.2 on 3 November. Its brainstorming skill now asks only questions whose answers would change what gets built, states a default otherwise, and opens with the user's motivation; in the maintainers' test scenario it offered options with a recommendation in 8 of 8 runs versus a bare question in 7.0.1. The release also repairs the session bootstrap on Copilot for Windows, Pi (now applied to every prompt), Hermes subagents, OpenCode and Muse, and makes the subagent-driven-development helpers act on the current repository with a -C DIR option. It is a useful example of one SKILL.md set being tuned to run across many agent runtimes.

Sources: obra/superpowers v7.0.2 release, obra/superpowers releases

3. Hermes Agent v0.22.6 adds per-skill locks that stop the agent writing to a skill on its own

Nous Research's Hermes Agent v0.22.6, dated 2 November, rolls up roughly 776 merged PRs. The one skills-specific line is "per-skill locks against autonomous writes", configurable from the Desktop Capabilities pane. The notes do not explain the mechanics and say fuller curated notes will arrive with v0.23.0, so treat the exact behaviour as unconfirmed. It still signals a pattern worth watching: agents that author their own skills now need a way to freeze the ones you trust, alongside a new pre_llm_call hook that can block a turn before inference.

Sources: Hermes Agent v0.22.6 release

4. OpenCode 2.2.3 splits managed policy so skills get their own skill.use permission

OpenCode v2.2.3, published 30 October, breaks the managed-policy model apart: integration.use now covers integration accounts only, while new mcp.use, skill.use and plugin.use actions govern MCP servers, skills and plugins separately. Existing rules with the mcp:, skill: and plugin: prefixes convert automatically, but a bare integration.use rule no longer reaches skills, so admins who relied on it must add explicit skill.use rules. For organisations rolling out shared SKILL.md libraries, this is the first-class per-skill allow/deny control that was missing.

Sources: OpenCode v2.2.3 release

5. Copilot CLI 1.0.106-6 keeps configured skills available on the first request and escapes control characters across the UI

GitHub Copilot CLI pre-release 1.0.106-6 (3 November) fixes a startup race so configured skills remain available on the very first request during reconciliation. It also stops terminal escape sequences in MCP connection errors, question forms, tool rows, memory text and web-fetch prompts from hiding or recolouring text, a hardening step relevant when skills and MCP servers supply untrusted strings. Additions include a unified /settings dashboard with search across settings and local resources, and MCP content meant only for the user is no longer sent to the model.

Sources: Copilot CLI v1.0.106-6 release
