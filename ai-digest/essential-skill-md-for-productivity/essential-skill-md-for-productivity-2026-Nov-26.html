1. OpenClaw 2026.11.10 goes stable with Deep Research on by default and an opt-in Knowledge vault plugin

OpenClaw published 2026.11.10 as its stable release on 25 Nov. The release notes count 7,671 pull requests from 349 contributors. The headline feature is Deep Research, which is on by default: ask your agent in chat and it researches across web sources or your own files, then returns a cited report. Where sources disagree it shows the quotes side by side, it lists open questions under Unresolved, and it keeps reports for seven days. Knowledge is an opt-in memory plugin, switched on with plugins.slots.memory set to "knowledge". It builds a local Markdown vault of people, projects and decisions from your chats, meetings and notes, keeps Git checkpoints of each revision, and leaves existing memory-core data alone. Agent Templates are still a lab feature, but they can now install bundled plugins and recommend one ClawHub plugin during setup. A 2026.10.34 patch for the older line followed on 26 Nov so updates finish when the config is read-only or old plugin leases are left over.

Sources: OpenClaw v2026.11.10 release, OpenClaw 2026.11.10 changelog, OpenClaw 2026.11.10 release notes (docs), OpenClaw releases (2026.10.34)

2. Copilot CLI 1.0.117 lets custom agents opt in to tools explicitly, and subagents now respect their tool lists

GitHub shipped two Copilot CLI pre-releases, 1.0.117-0 and 1.0.117-1, on 25 Nov, hours after 1.0.116 became the Latest release. The main addition is explicit tool exposure: a custom agent can now name the tools it opts in to, rather than getting everything by default. In 1.0.117-1, subagents also follow the tool list in their custom agent file even when that file has no prompt. That matters for anyone who writes small, focused agents next to their skills. The pre-releases also fix a trust issue: --trust-folder run from a subdirectory no longer runs the repository root's hooks when --add-dir names a folder in the same repo. They also stop plugins reloading again on each press of Enter at the trust prompt, and let background agents carry on after the CLI restarts. In 1.0.116 itself, the env setting now reaches every process Copilot starts, including hooks and MCP servers.

Sources: Copilot CLI v1.0.117-0 release, Copilot CLI v1.0.117-1 release, Copilot CLI v1.0.116 release, Copilot CLI releases

3. Claude Security plugin 0.13.1 makes you name where your scanned code is sent

Anthropic merged Claude Security v0.13.1 into its official plugin marketplace on 25 Nov (PR #7224), a day after 0.13.0. In the sandbox, the claude-security command now requires --provider, set to anthropic, bedrock, vertex or foundry, to say where the scanned code goes. A new --model-base-url option points it at a gateway, and only https addresses or local loopback hosts are accepted. Before the confirmation prompt, the command prints a line such as "Your code goes to Amazon Bedrock, configured by environment variables". It refuses to run if your environment or Claude Code settings name a different provider, or if managed settings turn off the variables it needs. Teams that run a security-review plugin in CI should add the new flag to their workflows. The CI examples now reference a release commit rather than a moving tag.

Sources: claude-plugins-official PR #7224, Claude Security v0.13.1 commit bd81c1a, claude-plugins-official commits

4. Google's Cloud Operator skills now stop and walk you through reconnecting, and the Agents CLI skill covers LangChain and the Claude Agent SDK

google/skills merged four commits on 25 Nov. In the most useful one (401f470), the google-cloud plugin's MCP servers share one sign-in token. The Cloud Operator skills (cloud-operator 1.3.0, cloud-operator-setup 1.2.0) also gain a four-step Server not connected procedure. When the server offers no tools or a call fails with a sign-in error, the agent says the server is disconnected, gives the sign-in and reconnect steps, and waits for you before it continues. Before, it might have tried to answer without the server. Any skill that depends on an MCP server can copy this pattern. A second commit (7f996a7) updates the google-agents-cli-onboarding skill to 1.1.0 for Agents CLI v1.15.0. It now lists LangChain, LangGraph and the Claude Agent SDK alongside ADK, documents both uvx google-agents-cli setup and npx skills add google/agents-cli, and maps each command to its lifecycle phase. The other two commits improve the pathways-workload skill, which now detects memory-pressure evictions, and remove an older data-science workflow skill.

Sources: google/skills commit 401f470 (Cloud Operator reconnect), google/skills commit 7f996a7 (Agents CLI onboarding), google/skills commit b315c2e (pathways-workload), google/skills commits

5. Google AdMob ships agent skills for adding ad code, with an AdMob MCP server in early testing (from 16 Nov)

This item is from 16 Nov, outside the 24-hour window: today's news was thin, so it comes from the wider fallback window. It hadn't been covered here yet. Google announced AI tools for AdMob, and the only one available now is a set of agent skills. They are prebuilt instructions that help coding agents such as Antigravity, Claude Code, Codex and Cursor add AdMob ad code to an app and check it. Coverage gives the install command as npx skills add google/skills/skills/ads, and Google's AdMob developer docs have "Use agent skills" pages for iOS and Android. An AdMob MCP server that would let agents read account data and change settings is in early testing. It is due to reach more developers early next year, and changes would still need your approval before going live. Ask AdMob, a Gemini assistant inside the AdMob web interface, starts testing over the coming months. For mobile developers, this is one of the first major ad platforms to publish official skills.

Sources: Google blog: new AdMob tools, AdMob docs: Use agent skills (Android), AdMob docs: Use agent skills (iOS), TechRepublic, PPC Land
