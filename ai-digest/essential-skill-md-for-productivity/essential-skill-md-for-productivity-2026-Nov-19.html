1. Google adds four CI/CD skills to its library, with a secret scan required before any deploy

On 18 Nov, Google's public skills repo added four Google Cloud CI/CD skills. google-cicd-deploy deploys static sites, containers, AI agents and MCP servers to Cloud Storage, Cloud Run or GKE. It requires a secret scan before every build and generates an SPDX SBOM. It also checks Binary Authorization policy and registers the deployed agent in Google Cloud's Agent Registry. google-cicd-pipeline-design covers trunk-based and tag-triggered pipelines on Developer Connect, Cloud Build and Artifact Registry. google-cicd-release-orchestration handles Cloud Deploy, Skaffold profiles, canaries, rollbacks and promotions, and google-cicd-terraform covers state, least-privilege IAM and Cloud Build triggers. Each skill's description names which sibling to use for the other jobs, so an agent picks one skill instead of loading all four. The same day Google added compute-resource-availability-troubleshooting, a 496-line skill for ZONE_RESOURCE_POOL_EXHAUSTED stockouts on GPUs, TPUs and scarce CPU shapes. It also lists the errors the skill should not handle, such as IAM and quota problems.

Sources: google/skills commit 2af5f95 (four CI/CD skills), google/skills commit d2b18e8 (compute-resource-availability-troubleshooting), google/skills commit history

2. Google ships three linked Spanner Graph skills, a warehouse export generator and a Data Manager API troubleshooter

Late on 18 Nov, Google added three Spanner Graph skills built as a set. spanner-relational-to-graph maps existing relational tables to CREATE PROPERTY GRAPH DDL without changing them. spanner-graph-schema-best-practices covers physical schema design, interleaving and edge folding. spanner-graph-query-tuning profiles GQL execution plans and applies query hints. Each description sends the agent to one of the other two for the jobs it does not cover. Together they add about 4,000 lines of instructions and references. bigquery-migration-data-exporter reads BigQuery Migration Service metadata and writes Parquet export SQL for Snowflake, Databricks, Teradata, Oracle and PostgreSQL. It never connects to the source database. On the ads side, a new data-manager-api-troubleshooting skill takes over the request-status diagnostics that the event and audience ingestion skills used to repeat. Each skill now holds less duplicated text, which means less context per load.

Sources: google/skills commit 212dcc4 (spanner-relational-to-graph), google/skills commit 78cc952 (spanner-graph-query-tuning), google/skills commit da00486 (spanner-graph-schema-best-practices), google/skills commit fadea16 (bigquery-migration-data-exporter), google/skills commit 609310d (Data Manager API troubleshooting)

3. Addy Osmani's agent-skills 0.6.17 adds an accessibility audit skill that fails rather than reporting false clean results

On 18 Nov, Addy Osmani's agent-skills library released 0.6.17 and merged PR #261, which had been open since early October. It adds accessibility-engineering, a skill that audits an existing interface against WCAG 2.2 AA and then fixes the confirmed violations. It runs pinned versions of @axe-core/cli 4.13.0 and pa11y 9.1.1. A bundled audit-a11y.sh script fails, instead of reporting a clean result, when either tool does not produce a valid report. The skill sorts findings into four severities and asks the agent to confirm each one in the browser. It treats automated checks as a smoke test only, so it also walks through keyboard, VoiceOver/NVDA, contrast, zoom and reduced-motion checks by hand. The release also adds an accessibility-auditor agent, an /a11y command for Claude Code and Gemini CLI, and evaluation cases for the skill. It sends new UI construction to the existing frontend skill instead. In the same release, the code-review skill now checks that the checkout is clean and on the reviewed commit before running tests.

Sources: addyosmani/agent-skills (GitHub), PR #261: accessibility-engineering skill, PR #795: code review checks the checkout, accessibility-engineering SKILL.md

4. Claude Code 2.1.328 fixes /goal deleting a skill's Stop hook and loads managed plugins sooner on new machines

Claude Code 2.1.328 came out on npm at 23:09 UTC on 18 Nov. It fixes several problems in how skills and plugins behave. Before, /goal could remove a skill's own Stop hook, or end early, when another hook had the same wording. Code Mode could also lose a loaded skill after resuming a session in which one reply ran several scripts. In the /plugin manager, fixes cover reopening the wrong skill after a slow save, offering to uninstall the wrong plugin, and holding Enter turning off several plugins. The /usage plugin total also no longer stops at 2,000 tokens on 1M-context models. For teams, plugins from managed settings that live in a git marketplace now load sooner on a fresh machine, and claude -p and SDK sessions fetch them in the background. Apps that embed Claude Code can now turn on the policy plugin's allowManagedModsOnly option. If your team uses skills with Stop hooks together with /goal, upgrade.

Sources: Claude Code CHANGELOG (2.1.328), Claude Code changelog, npm: @anthropic-ai/claude-code

5. awesome-copilot adds an Agent Session Board for supervising several Copilot sessions, plus a .NET API design skill

GitHub's awesome-copilot repo merged PR #6491 late on 18 Nov. It adds the Agent Session Board, a canvas extension for supervising several Copilot agent sessions working on one repository. A "Waiting on you" panel collects questions that agents post, and agents read the answers back with get_answers. Each answer is tied to the exact version of its question, so editing a question doesn't carry over an old answer. The board also shows, for each PR, the first merge check it has not yet passed (draft, conflict, CI, review, branch rules). It also shows progress per milestone and merges over the last 24 hours and 7 days. The PR went through five rounds of review in one day, which added bounded queues, lock ownership checks and accessible data tables. The same day the repo merged polytype-middleware (PR #6414). It is a narrow skill for keeping a PolyType library's API complete on net472 and netstandard2.0. It also bumped the New Relic plugin to 0.3.0 with a new Kafka skill.

Sources: PR #6491: Agent Session Board, PR #6414: polytype-middleware skill, PR #6475: New Relic 0.3.0 with Kafka skill, github/awesome-copilot commit history
