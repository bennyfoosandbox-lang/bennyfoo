1. Claude Code 2.1.321 stops project skills vanishing after git stash or a worktree switch

Claude Code v2.1.321 (9 Nov) fixes a bug where project skills, commands and agents stayed missing after their folder was removed and restored mid-session, such as with git stash, including after entering a worktree. A second fix keeps project skills from dropping out of the menu in SDK and desktop sessions once Claude enters a worktree. It also refuses skill and command names containing a Bamum letter that some fonts render blank, which closes a lookalike-name gap, and stops plugin auto-updates from re-downloading a plugin for every worktree. For anyone who branches often with skills checked into the repo, this removes a source of skills silently disappearing mid-task.

Sources: Claude Code v2.1.321 release notes, Claude Code releases

2. Anthropic moves its docx, pdf, pptx and xlsx skills to Apache 2.0

On 6 November, anthropics/skills merged PR #2146, which relicenses the four Office skills (docx, pdf, pptx, xlsx) under Apache 2.0, the same license as most other skills in the repo, and updates the README to match. These four are among the most-copied productivity skills because they handle everyday documents, and the earlier source-available terms had kept teams from bundling them freely. Downstream projects reacted within hours: one agent-office repo re-pinned to the new commit and imported the four skills as Apache-2.0 official copies, and a scientific-writing repo opened a legal-fix PR to bundle them. Third-party directories that still describe the skills as proprietary are now out of date.

Sources: anthropics/skills PR #2146, anthropics/skills commit history

3. Copilot CLI 1.0.108 ships and 1.0.109-0 keeps skill problems visible in long lists

GitHub Copilot CLI 1.0.108 went stable on 9 November, promoting the earlier pre-release changes: skill names now match case-insensitively in disabledSkills, skills.disable and skills.enable, a path or URL in a prompt no longer loads a skill named after its first segment, and a warning appears when a custom agent's configured skills are missing or fail to load. The 1.0.109-0 pre-release adds a smaller quality-of-life change that keeps selected skill problems visible while you scroll long /skills problem lists. This is an update to the pre-release coverage logged on 7 November, since the fixes are now in the stable channel.

Sources: Copilot CLI v1.0.108, Copilot CLI v1.0.109-0, Copilot CLI releases

4. Langfuse adds versioned skill management, linked to agent traces

Langfuse's 3 November changelog introduces skill management in beta, letting teams store and version agent skills and connect them to the traces their agents produce. The practical point is that a SKILL.md edit can now be tied to an observable change in agent behavior, which is the missing feedback loop for teams that tune skills by feel. It sits alongside a similar October beta from LaunchDarkly for managing skills, a sign that skills are being treated as deployable, versioned assets rather than loose files. Details here come from the changelog entry as surfaced in search; the page itself was not reachable from this environment.

Sources: Langfuse changelog: skill management

5. The mcp-builder skill now teaches version 2 of the MCP TypeScript SDK

The anthropics/skills repository updated its mcp-builder skill on 28 October (PR #2087) so that agents scaffolding MCP servers target v2 of the MCP TypeScript SDK instead of the older API. Because mcp-builder is the reference skill many teams copy when wiring tools into agents, the change quietly updates what a large share of generated servers will look like. This item is about 13 days old and is included because the 24-hour window produced fewer than five novel, verifiable items; it has not appeared in earlier digests.

Sources: anthropics/skills commit history
