1. Claude Code 2.1.301 adds claude-api tracing guidance, caps skill argument expansion and fixes a Fable alias fallback

Claude Code v2.1.301, published on 15 October, extends the bundled claude-api skill with OpenTelemetry tracing guidance, including how to set up trace destinations with the ant CLI. It also fixes a real productivity drag for heavy skill users: skills and commands with very many or very long argument names no longer stall for seconds on invocation (only the first 64 names, each up to 64 characters, are filled in), and skills, commands and hooks no longer balloon in memory when arguments fill many placeholders. Further additions include new OpenTelemetry tool_decision fields that distinguish auto-mode classifier verdicts from permission rules, a retry-watchdog cap for unattended runs hitting far-off usage limits, and a fix so the fable model alias retries on the previous Fable model when the newest is unavailable to an organization.

Sources: Claude Code releases (v2.1.301)

2. Copilot CLI 1.0.99 prereleases add one-link skill and plugin installs and a trust-folder flag for scripted runs

GitHub's Copilot CLI 1.0.99-1 (15 October) lets users install verified Skills and plugins straight from a GitHub install link with copilot plugin install "ghapp://air/install?...", removing the manual clone-and-copy step for sharing a skill. It also adds --trust-folder for one-off prompt-mode sessions started with -p or piped stdin, which matters for unattended skill-driven scripts. The follow-up 1.0.99-2 (16 October) turns semantic code search on by default for online sessions, shows a clear notice when administrator-managed settings override the chosen model, and lets chats start while optional managed plugin downloads finish in the background. These are still prereleases; 1.0.98 remains the latest stable build.

Sources: Copilot CLI releases (1.0.99-1, 1.0.99-2)

3. Terra API ships ten agent skills so coding agents stop guessing health-data integrations

Health-data platform Terra API published ten SKILL.md skills in tryterra/agent-skills, covering the unified API, mobile SDKs, streaming, lab-report parsing, a CLI and an admin MCP server. The flagship terra-unified-api skill carries 21 ranked rules written as explicit instructions, such as verifying webhook signatures against the raw body, acknowledging inside the eight-second window, deduping chunked deliveries by trace ID and never overwriting a score with a null. Install is one command (npx skills add tryterra/agent-skills), or via terra agent setup, or as a plugin for Claude Code, Codex and Cursor. It is a clear example of a vendor using skills as the supported way to keep agents on current API behaviour rather than model memory.

Sources: Terra: agent skills for building health products, tryterra/agent-skills on GitHub

4. LangChain's Deep Agents lets skills bind tools, pin on demand and reload mid-thread

From earlier this month (7 October, picked up here because it is new to this knowledge base), LangChain revamped skills support in Deep Agents around three features. Tools bound to a skill through metadata.include_tools stay out of context until the agent reads that skill, and on models that accept mid-conversation tools the prompt cache stays intact. Pinned skills let an app load a skill such as /meeting-prep before the first model call, saving a round trip, and skills_metadata can be set to None to reload a library mid-thread. LangChain says enterprise registries are growing to thousands of skills, and its own GTM agent already runs more than 50.

Sources: LangChain: Revamping Skills in Deep Agents

5. Google's Android skills bring the open SKILL.md format to Android development via the Android CLI

Google's Android developer documentation describes Android skills: SKILL.md instruction packages for tasks like migrating XML to Compose, upgrading to AGP 9, adopting Navigation 3, going edge-to-edge and auditing R8 configuration. They follow the open agent skills standard, install with android skills list and android skills add through the Android CLI for any agent, and can be imported into Android Studio, where @skill-name invokes one manually. The docs set concrete authoring limits (names up to 64 characters, descriptions up to 1024, bodies of roughly 10k-20k characters) and look in .skills/ or .agent/skills/ at the project root. The page was last updated on 25 September, so this is a widened-window pick, but it is the first Android coverage in this knowledge base and community write-ups surfaced it again in the last day.

Sources: Android Developers: Overview of Android skills
