1. Claude Code 2.1.331 lets plugins ship optional dependencies, and stops a failed update from leaving skills missing

Claude Code 2.1.331 is the newest entry at the top of the official changelog. For anyone who packages skills as plugins, the main change is a new optionalDependencies field in plugin manifests. Plugins listed there install with the plugin that names them, but users can disable or uninstall them separately, so an author can bundle helper skills without forcing them on everyone. The release also fixes an interrupted or failed plugin update that left a partial plugin folder, which later loaded with skills or other parts missing (#102186). It fixes PermissionRequest hooks that did not save Skill(name:*) allow rules outside local settings, and a hook's reason for stopping a forked skill appearing twice. Admins should also note a coming change: on or after 30 Nov, marketplaces listed in managed extraKnownMarketplaces will auto-update by default unless their entry sets "autoUpdate": false.

Sources: Claude Code CHANGELOG.md, Claude Code changelog (docs), Issue #102186

2. Codex 0.172.0 teaches its bundled docs skill the GPT-6.2 migration, and starts optional MCP servers only when first needed

OpenAI tagged Codex CLI 0.172.0 as the latest release on 24 Nov. The bundled openai-docs skill now covers moving to GPT-6.2 Astra and Sol, including which endpoints to choose and the tool-calling requirements (#62447). That gives teams that rely on the skill for API work a ready migration guide inside the agent. Optional stdio MCP servers with cached tool lists now start on their first tool call by default, which cuts startup cost for setups with many skills and servers. Users can also set an approval reviewer for individual connected-app tools in config.toml. Extensions can attach metadata to MCP tool requests, and Codex now measures how long plugin recommendations take during initial context setup (#62326). Other additions are Tab completion for slash-command arguments such as /mcp login, and codex exec resume now restores saved sandbox permissions and workspace roots.

Sources: Codex rust-v0.172.0 release, Codex releases, PR #62447

3. OpenClaw 2026.11.10-beta.2 lets plugins fork a live session for background work, and keeps skill secrets out of plaintext

OpenClaw published 2026.11.10-beta.2 as a pre-release on 23 Nov, after the 2026.11.7 stable build covered here yesterday. The main new feature lets plugins fork a session's live context to run background work. The forked work uses the plugin's own tools, and policy controls its file and command access, which gives skill and plugin authors a supported way to do side tasks without blocking the main chat. A security fix keeps the existing SecretRef when someone edits a secret-backed skill key on the Skills page or through skills.update. Before the fix, an edit could overwrite the reference with plaintext. The beta also keeps finished subagent results across Gateway restarts and sends new instructions to busy subagents right away. The ClawHub registry update reports all 105 plugins published, but the release notes say the full validation run failed and was signed off with recorded waivers, so this build is best kept to testing.

Sources: OpenClaw v2026.11.10-beta.2 release, OpenClaw releases

4. Runtime testing finds about 1 in 40 agent skills act maliciously, and most get past static scanners

An article on Okta's newsroom by Ian Ahl, who leads Permiso's P0 Labs, gives results from 35,286 runs in SandyClaw, the company's sandbox that runs skills and records what they do. The team reports that about 1 in 40 agent skills behaved maliciously when run: 517 malicious results across 21,850 runs of 16,836 unique skills. The article says static scanners missed 92% of the malicious behaviour before it ran. Packages from public registries such as npm and PyPI came out worse, with 32% (4,037 of 12,679) judged malicious when run. The article was published 18 Nov, so it comes from this run's 7-day fallback. The figures are the vendor's own and the localized versions describe the 92% differently, but the advice is clear: run a third-party skill in a sandbox and watch what it does before you install it, rather than trusting a scan of its text.

Sources: Okta newsroom: The 1-in-40 risk, Okta newsroom (German edition), IT Brief: Permiso launches SandyClaw

5. Google's cloud-network-insights skill now asks before risky steps, and Anthropic hardens its official plugin scan pipeline

Two skill publishers tightened guardrails on 23 Nov. In google/skills, the cloud-network-insights skill now tells the agent to ask the user before it accepts third-party terms, turns the product off or deletes resources. It also has the agent delete policies and Monitoring Point records one at a time by ID, rather than in bulk. The same day brought a clarified usage-attribution note in agent-platform-architecture (v1.0.2) and a skill-name fix in detection-engineering-coverage-evaluation. In anthropics/claude-plugins-official, PR #7206 ("Plugin workflows: hardening") moves the verdict cache and scan policy out of the checkout, pins the shared GitHub Actions again, and stops the scan from installing a CLI. The security-guidance plugin also now states what its hooks report as usage data. Both are small changes, but they show where skill authoring is heading: confirm before destructive or legal steps, and keep the review pipeline for marketplace plugins out of reach of the code it checks.

Sources: google/skills commit 22afb84 (cloud-network-insights), google/skills commit 6393465 (agent-platform-architecture), google/skills commit 8123e48 (detection-engineering), claude-plugins-official PR #7206, claude-plugins-official commits
