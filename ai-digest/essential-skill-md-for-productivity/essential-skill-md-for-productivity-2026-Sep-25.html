1. Claude Code v2.1.282 caps prose width and stops undecryptable web-search history from killing conversations

Anthropic shipped Claude Code v2.1.282 on September 24, adding a maxProseWidth setting that caps prose in wide terminals while tables and code blocks keep full width, plus a startup notice and /status / claude doctor entries that surface which telemetry variables a project's settings quietly ignored or turned off. The release's most consequential fix closes a class of 400 errors that killed conversations outright when history held web-search results the API could no longer decrypt, letting those threads continue instead of dying on replay. It also stops extended thinking from being silently dropped when /model, /rename, /artifacts or another slash command fires mid-turn, and cleans up /skills and /mcp list rendering along with several vim-mode and Unicode-in-permission-prompt bugs. For teams running Claude Code unattended — exactly the audience this digest tracks — the decrypt-failure fix matters most: it removes a silent failure mode that could otherwise strand a long-running session with no recovery path.

2. SkillApt teaches agents when to skip a matched skill, cutting activation to 31.5% with no accuracy loss

A new paper, "SkillApt: Learning When to Activate Agent Skills from Counterfactual Evidence," argues that retrieval and activation are two separate decisions: a retrieved skill can be relevant yet still unnecessary, costly, or actively harmful to load in the current execution state. SkillApt is a post-retrieval controller that builds per-skill evidence from matched WITH/WITHOUT executions, then aggregates outcomes from similar historical states to make a LOAD-or-ABSTAIN call for a new one. On the frozen SRA-Bench confirmatory evaluation, SkillApt-E matched BM25 Top-1's observed accuracy (0.838 vs. 0.838) while cutting the activation rate from 100% to 31.5% and mean token usage by 74.3%. For anyone building a productivity skill library, the finding cuts against "load every matching skill by default": most of the token and latency cost in a skill-heavy setup comes from skills that fire but don't help, and a cheap activation gate can strip most of that cost out without touching accuracy.

Sources: arXiv:2609.26863, Full text (HTML)

3. Devin retires "Knowledge" notes for Skills, then spends a week fixing what broke

Cognition's Devin began migrating its legacy "Knowledge" notes into Skills on September 18, converting existing notes automatically into a knowledge plugin for each scope — organization, enterprise, or personal — with content and folder structure preserved; once a workspace is migrated, its old Knowledge page goes read-only and points to Customize → Skills instead. The following week's changelog was mostly cleanup from that switch: invoking a skill now passes the entire SKILL.md to the model instead of truncating it to the tool-result budget, $ARGUMENTS and $1–$9 placeholders now interpolate correctly when a skill is called, and skills discovered mid-session are re-listed after context compaction instead of silently disappearing for the rest of the run. Skills, rules, hooks and subagent profiles that come from an installed plugin are now also labeled with the plugin's name across Devin's lists, closing a gap where a shared plugin's contents were indistinguishable from locally authored ones. It's a useful case study in a pattern this digest keeps seeing: standardizing on SKILL.md as the single format is the easy part, and the real work is the week of truncation, interpolation and labeling bugs that surface once real teams start relying on it.

Sources: Devin release notes, Releasebot: Devin updates

4. GitHub Copilot CLI ships four v1.0.89 point releases in three days, wiring in Claude Opus 5.5 and GPT-6

GitHub pushed four back-to-back Copilot CLI releases — v1.0.89-0 through -3 — between September 22 and 24. The run opened with Claude Opus 5.5 support and a copyable authorization URL for managed-connector consent, then added GPT-6 Sol and GPT-6 Luna to the model picker, fixed the view tool to honor line ranges when a provider sends flattened view_range arguments, and let MCP pre-registered OAuth clients honor their configured scopes. Smaller fixes rounded out the run: sandboxed commands can now reach localhost on supported Windows versions when local network access is enabled, /model and /model plan argument pickers autocomplete model IDs, and ask-user forms keep custom "Other" answers separate across questions instead of bleeding into each other. For a CLI teams increasingly run as an unattended agent, the pace — four releases in three days, each shipping real model and reliability fixes — says as much about GitHub's Copilot release cadence as any single change in the batch.

Sources: v1.0.89-0 release notes, v1.0.89-3 release notes, Full releases index

5. OpenClaw traces its 2026.9.6 crash-loop to an 8-byte stack-frame bug and merges the fix

A day after OpenClaw pulled its 2026.9.6 macOS build from the Sparkle update feed for bricking launches, engineers found the actual root cause: the compiled ARM64 binary allocated only 112 bytes for an async sleep frame that needed 120, corrupting memory on every launch and crash-looping the app. The fix landed as a merged pull request on September 24, with a 2026.9.7 preflight build — using the shipped toolchain and a mandatory binary audit — set as the release's remaining proof gate before it ships. Affected users are still directed to reinstall the 2026.9.5 build from OpenClaw's releases page in the meantime; the npm/Gateway package was never affected, only the macOS app. It's a reminder that a withdrawn release isn't the same as a diagnosed one — the eight-byte miscalculation here is the kind of bug a Sparkle rollback alone wouldn't have caught without someone reading the disassembly.

Sources: Merged fix PR #156881, Original crash report #156861
