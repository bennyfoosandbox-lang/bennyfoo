1. Claude Code 2.1.293 makes Haiku 5.5 the default Haiku and plugs an MCP memory leak

Claude Code 2.1.293 shipped on 7 October, one day after the sub-agent effort release. Its headline change adds Claude Haiku 5.5 (claude-haiku-5-5) as the default Haiku model on the Anthropic API, with a 1M-token context window. That is the cheap, fast tier most people use for sub-agents and skill-heavy loops, so the new default changes cost and speed with no config edit. The release also fixes a memory leak where an HTTP MCP connection retained every request it had sent until it closed, which matters for long sessions with many MCP-backed skills. A third fix makes `claude purge` keep going when one file cannot be deleted, then list the failures and exit 1.

Sources: Claude Code v2.1.293 release notes, Claude Code releases

2. Codex CLI 0.161.0 makes GPT-6.1 Sol the default and adds in-terminal MCP sign-in

OpenAI's Codex CLI promoted 0.161.0 to Latest on 7 October. GPT-6.1 Sol becomes the default model in the bundled and Amazon Bedrock catalogs, so agents that load SKILL.md packs now run on it by default. The new `/mcp login <name>` command lets you authenticate an MCP server from an active terminal session instead of leaving to do it elsewhere, removing a common stall for tool-backed skills. Voice conversations also gain microphone, speaker and input-channel pickers, with preferences saved locally. The 0.162.0 alpha line is already at alpha.17 and alpha.18, so the next minor is close behind.

Sources: Codex CLI releases, Codex CLI 0.161.0

3. Copilot CLI 1.0.93 goes stable with sandboxing for everyone, and 1.0.94 pre-releases follow the same day

GitHub promoted Copilot CLI 1.0.93 to Latest on 7 October, turning the earlier pre-release features into a stable build. Command sandboxing is now available to all users through `/sandbox` and `--sandbox`, enterprise `permissions.limitTo` enforces managed domain boundaries for network requests, and MCP server configuration changes apply between turns without restarting the session. A 1.0.93-4 pre-release also kept plugin skill commands available after reloading plugins, which is directly relevant to skill authors. Three 1.0.94 pre-releases landed the same day, adding update guidance when managed settings need a newer CLI and letting managed policy keep sessions in Manual Approval mode.

Sources: Copilot CLI releases, Copilot CLI 1.0.93, Copilot CLI 1.0.94-0

4. Gemini CLI 0.64.0 preview and 0.65 nightlies tighten folder trust and fix session resume

While 0.63.0 remains Latest, Google's Gemini CLI cut a 0.64.0 preview on 6 October and 0.65.0 nightlies on 7 and 8 October. The preview migrates a2a-server settings from V1 to V2, bridges prompt usage data into ACP with usage-update notifications, and propagates the resolved folder-trust state in headless mode. The nightlies make workspace settings read-only in untrusted folders, avoid duplicate tool-response turns on resume, and stop resumed session history being deleted on a quick exit. Together these harden the places where repo-supplied skills and settings get loaded, and a nightly adds custom OTLP headers for telemetry.

Sources: Gemini CLI releases, Gemini CLI 0.64.0-preview.0

5. OpenClaw 2026.10.1-beta.2 routes background skill reviews through Workshop proposals

OpenClaw published its second 2026.10.1 beta on 8 October, three days after beta.1 and following the 2026.9.8 stable. Per the release notes, background skill reviews are now routed through Workshop proposals, so skill changes surface as reviewable proposals rather than silent edits. The beta also adds local Claws migration for existing agents and a long list of deprecations with removal targets, across sessions and memory, Doctor and updates, cloud workers, and plugins, Codex and MCP. The 2026.8.34 and 2026.8.35 builds earlier in the week had already tightened skill scanning boundaries and repaired read-only copied skills.

Sources: OpenClaw releases
