1. Microsoft opens Ignite with more than 100 prebuilt business skills for Copilot

On 17 Nov, at the start of Ignite in San Francisco, Microsoft announced that its Dynamics 365 plugins for Copilot are now generally available. Each plugin bundles a job's know-how with secure data access and tools. Jared Spataro's Copilot post counts more than 100 prebuilt skills across the Sales, Service and Finance & Operations plugins: 44 for sales, 13 for customer service, 30 for finance and more than 20 for legal. A new Salesforce in Copilot plugin adds more than 38 prebuilt sales skills. Jeff Teper's Dynamics post describes skills for account plans, meeting prep, deal catch-ups, purchase requisitions and requests for quotes. Microsoft's internal study of its own sellers reports 25% less effort and 9% faster deal closure, but those are vendor telemetry figures, not an independent result. For productivity, this is the biggest single drop of packaged, role-specific skills into a mainstream work app so far.

Sources: Microsoft Copilot blog (Spataro), Dynamics 365 blog (Teper), Microsoft Tech Community: Plugins at Ignite 2026, Ignite 2026 Book of News

2. Agent 365 makes skill governance GA, and a skills recorder turns an Edge workflow into a shareable skill

Ignite also brought admin control over skills. Microsoft says plugin and skill governance in Agent 365 is now generally available. From the Microsoft 365 admin center, admins can control which plugins and skills are available and assign them to specific users and groups, with MCP server controls alongside. Microsoft also showed a skills recorder for Copilot Cowork. A user does a multi-step process once in Edge for Business and saves it as a reusable skill that teammates can share. Its status is unclear: the Book of News calls it a preview with Cowork, while some trade coverage expects the preview by the end of 2026 and leaves it off the GA list. Azure Copilot custom skills and spaces entered public preview, and the ARM MCP Server gained an experimental Skills toolset that clients have to opt into with a request header. 3. Itential releases 40 open-source infrastructure skills organized by capability, not vendor

On 17 Nov, Itential announced Infrastructure Agent Skills, an Apache-2.0 library of operating procedures for agents that run networks and infrastructure. The repo has 40 capability skills, including firewall, DNS and IPAM, certificates, SD-WAN onboarding, change and incident management, Terraform plan execution and log or metric queries, plus 154 vendor references. Each SKILL.md works as a router: it points to an INDEX.md that maps each vendor to its own procedure.md and endpoints.md. The agent therefore loads only the details for the platform it is working on. The library follows the Agent Skills spec, and a CI workflow checks the name and description length limits on every PR. The README suggests keeping each SKILL.md under about 500 lines or 5,000 tokens. It is separate from Itential's Builder Skills, covered on 23 Oct, and the router-plus-vendor-reference layout is a pattern any team with multi-vendor tooling can copy.

Sources: itential/infra-agent-skills (GitHub), PR #117: Agent Skills conformance and validation, PR Newswire: Itential introduces Infrastructure Agent Skills, Futuriom

4. Google's skills library adds Gerrit code review, Kueue troubleshooting and Service Health incident correlation

Google's public skills repo merged about ten commits on 17 Nov, and three of them add new skills. gerrit-code-review uses a standard-library Python CLI to read and manage reviews on AOSP, Chromium, Fuchsia or self-hosted Gerrit. It covers diffs, comments, votes and cherry-picks, requires explicit user confirmation before every write action, and wraps Gerrit text in untrusted-data tags. gke-kueue-troubleshooting adds 26 files and 20 Python scripts for a six-stage diagnosis of batch workloads that won't admit. It runs only read-only commands itself and leaves any fix that changes resources to the user. servicehealth-incident-correlation checks whether a Google Cloud incident actually affects your project. It returns verdicts such as IMPACTED or INCONCLUSIVE and never treats a failed API call as an empty result. Read-only steps, confirmation before writes and honest "inconclusive" verdicts make these useful templates for your own operational skills.

Sources: google/skills commit 92db677 (gerrit-code-review), google/skills commit a429849 (gke-kueue-troubleshooting), google/skills commit 739e294 (servicehealth-incident-correlation), google/skills commit history

5. Claude Code 2.1.327 lists broken skill files in /status and fixes duplicate skill rows in the / menu

Claude Code 2.1.327 came out on 17 Nov (npm, 20:33 UTC). /status now lists broken agent, skill, command and output-style files, along with keybinding errors, ignored permission settings and hook matchers that never match. A skill that silently fails to load now shows up in one place. A bug fix stops the / menu from showing a row for each skill that shares a name when every row ran the first one. Plugin-delivered agents are no longer dropped when a session is resumed from the picker. claude plugin eval now keeps its deny rules even when a plugin has a permission hook, and flags calls the hook let through. If you maintain a personal or team skill set, run /status after upgrading to catch any broken skill files.

Sources: Claude Code v2.1.327 release notes, Claude Code changelog, npm: @anthropic-ai/claude-code
