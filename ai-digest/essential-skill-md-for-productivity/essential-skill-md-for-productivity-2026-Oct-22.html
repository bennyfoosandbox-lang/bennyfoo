1. Skills over MCP is now an official extension, and Bloomberg explains how its Terminal assistant shaped it

Bloomberg published the inside story of SEP-2640, the Model Context Protocol extension that lets an MCP server serve SKILL.md skills alongside its tools. The spec went Final on September 13, and it defines skills/list and skills/get methods, skill:// URIs, and a manifest of file sizes and SHA-256 digests. A connected agent loads a skill's files only when it needs them, and a skill updated on the server reaches every client with no reinstall. Bloomberg's ASKB team moved from files bundled with the agent to this model because it stopped scaling past one team. Security is treated carefully: skill content counts as untrusted input and needs per-skill user approval. The next item on the MCP roadmap is progressive discovery, so agents can search a catalog of thousands of skills instead of loading every description.

Sources: Bloomberg, MCP SEP-2640 spec

2. Five weeks after the spec, only four public MCP servers serve skills the standard way, while seventeen use home-made tools

API Evangelist probed 9,170 public MCP endpoints from 3,765 providers to see who has adopted the Skills Extension. Of the 1,450 that answered anonymously, four declare it and serve real skills: Hugging Face (SageMaker deployment and CLI skills), Glean, Renoolab and BestPrice. A further seventeen, including AWS, Timescale, Anthropic and Browser Use, already expose skills through their own tools, each with a slightly different name and shape. The protocol picture is a drag on adoption as well: only 44 endpoints negotiate the current 2026-07-28 revision. The takeaway for anyone writing skills is that demand predates the standard, and the easiest conversions are vendors whose product docs are already SKILL.md files.

Sources: API Evangelist, MCP Skills Extension docs

3. JFrog extends AI-SEC to scan skills for malicious intent and cites 969 malicious agent skills in the wild

JFrog announced new AI-SEC features that scan agent skills, plugins and APM packages, detect shadow AI on developer workstations, and let customers use their own LLM account for the scanning. Its supply-chain report counts 969 agent skills carrying high-impact malicious payloads. The company's argument is that a SKILL.md carries instructions rather than code, so SCA and SAST have nothing to trace, and a single sentence telling the agent to send a credentials file in its summary is valid Markdown with no CVE. It also cites a July research paper in which cloaked malicious skills evaded eight scanners more than 90% of the time. JFrog's proposed controls are semantic scanning, policy that blocks or queues findings, and enforcement each time an agent invokes the skill.

Sources: JFrog press release, JFrog blog, StreetInsider

4. vlt 1.5.0 adds a vlt skills command that links skills shipped in npm dependencies into your agent's folders

Packages increasingly ship a SKILL.md next to their code, but it ends up buried in node_modules where agents never look. The new vlt skills command lists those skills and links the ones you pick into .agents/skills, plus .claude/skills when that folder exists. The choice is saved as allow-skills in vlt.json, so teammates running vlt ci get the same set and the links follow the lockfile version when a dependency updates. By default it filters with :not(:malware) using Socket's alerts. Socket notes that pnpm 12.11.0 added a similar linking step earlier this month, so skill management is becoming a package-manager job.

Sources: Socket, vlt docs

5. Two Claude Code plugins keep your task list and CLAUDE.md current between sessions

An XDA Developers write-up, surfaced on daily.dev, finds that Claude Code's auto memory is hit-and-miss and stores notes outside the project. The author pairs the productivity plugin, which keeps a plain-text task file updated through /productivity:update and asks for clarification rather than guessing shorthand, with claude-md-management. That second plugin adds /revise-claude-md and a claude-md-improver skill that graded one CLAUDE.md 79 out of 100 and flagged missing details such as folder names with spaces. It only adds lines and never removes old ones, so the file needs manual trimming. The workflow change is to end each session by approving new rules rather than closing the window.

Sources: daily.dev summary of XDA Developers
