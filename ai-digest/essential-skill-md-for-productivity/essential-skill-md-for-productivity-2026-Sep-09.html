1. Claude Code ships /skill-doctor to show which loaded skills are quietly taxing every turn

Claude Code 2.1.261, released 4 September 2026, added a new /skill-doctor command that audits a session's actual skill usage: for every skill currently loaded, it reports whether that skill was ever invoked and what it costs in context on each turn. The underlying problem it targets is easy to miss — every skill in the active listing gets added to context on every single turn regardless of whether Claude ever uses it, and that listing budget defaults to 1% of the model's context window, so an accumulation of rarely-used skills silently eats into the space available for the actual task. Running the command surfaces exactly which entries are dead weight so a developer can disable or prune them, converting a vague sense that "the assistant feels slower" into a concrete, actionable list. It's a small addition but a directly on-topic one for this digest's core thread: as teams accumulate dozens of SKILL.md files across a project, the productivity case for skills increasingly depends on tooling that keeps their overhead visible and manageable, not just on writing more of them.

Sources: Implicator.ai, AI in Plain English, Julian Goldie: Claude Code Skill Doctor

2. Reporting points to OpenAI quietly building Anthropic-style "Managed Agents" for Codex, ahead of DevDay

On 7 September 2026, TestingCatalog's Alexey Shabanov published a codebase-reading piece arguing that OpenAI is preparing a Managed Agents offering that "broadly follows what Anthropic currently offers" — a hosted surface for configuring environments, skills, and plugins around Codex, aimed at a more business-focused deployment experience, ahead of OpenAI's DevDay on 29 September 2026. Progressive Robot's 8 September follow-up is notably more skeptical about the strength of that evidence: it points out the reporting is inference from interface strings rather than a confirmed feature, that the word "Codex" doesn't actually appear in the source material, and lays out three things that would turn the rumor into fact — a reachable agents UI, a published price or billing unit for the runtime, and an explicit statement about where execution happens. If it does ship close to what's described, it would put OpenAI's skills/plugins packaging on a similar one-click-deploy footing to Claude's own Managed Agent Platform, which this digest has tracked expanding its per-session skill cap and adding GitHub-sourced skill discovery earlier this year. For now it remains speculative, but it's the clearest signal yet of where Codex's skills story is headed next.

Sources: TestingCatalog, Progressive Robot

3. GitHub Copilot's weekly release adds Agent Merge and lets Claude sessions run in every workspace folder

GitHub's "Copilot weekly releases — August 31" changelog post, published 4 September 2026, introduces Agent Merge in public preview: it automatically gets a pull request ready to merge by resolving review feedback, fixing failed checks, and untangling merge conflicts on its own, cutting one more manual step out of the review-to-merge loop. The same release makes multi-root workspaces experimental in VS Code, which brings both Copilot and Claude agent sessions to every folder in a workspace rather than confining them to a single root — useful for the monorepo and multi-service setups where a skill or agent session previously had to be re-launched per folder. It also expands model choice (Claude Fable 5.1 now available to Copilot Pro+, Max, Business, and Enterprise users; Gemini 3.8 Flash rolling out more broadly) and adds chat-session hierarchies that surface which sessions still need attention. None of this is skills-specific in isolation, but together it's the kind of incremental harness work — less friction moving agent sessions and their loaded skills across a real, multi-folder codebase — that determines whether skills-based workflows actually save time day to day.

Sources: GitHub Changelog, Tech Bytes coverage

4. MCP's "Skills Over MCP" working group pushes to make reusable skills discoverable through the protocol itself

A September 2026 piece from Aembit, syndicated on Security Boulevard, lays out where the Model Context Protocol is headed next beyond simple tool-calling: a Tasks extension for delegating long-running work without holding a request open, MCP Apps for servers to render interactive HTML interfaces inside a host, enterprise-managed authorization so an organization can scope what an agent may access under one identity rather than per-user per-server grants — and, most relevant here, an active Skills Over MCP Working Group. That group is developing an experimental extension specifically for discovering and distributing reusable agent skills through MCP servers, rather than only through a local skills/ folder or a marketplace install — meaning a skill could in principle be served, versioned, and permissioned the same way an MCP tool already is today. It isn't part of the official MCP specification yet, so nothing here is shipping to end users this week, but it's a meaningful signal that the protocol layer underneath most agent harnesses is moving toward treating "skill" and "tool" as points on the same discoverable, governed surface rather than two separate systems bolted together. That convergence is one this digest has been tracking since MCP's stateless-core rewrite and Microsoft's own MCP-based skill discovery work earlier this year.

Sources: Security Boulevard, Aembit

5. Anthropic goes public on the Claude session-hijacking campaign this digest first flagged in August

This digest's 31 August entry logged early researcher reports of infostealer malware stealing Claude login-session cookies; Anthropic has now confirmed the campaign directly to affected users and named names. In outreach reported this week, the company says common infostealers — Vidar, LummaC2, StealC, Redline, and Acreed on Windows, plus Atomic Stealer on a small number of Macs — have been lifting saved browser passwords and login cookies from infected PCs, and that stolen session tokens let attackers into a Claude account without needing a password or tripping MFA. Anthropic's stated response is to sign out affected users, remove any saved payment methods, and refund charges it identifies as unauthorized; it stresses the malware itself has no connection to Claude and typically arrives through unrelated downloads or malicious apps, not through anything the user did inside Claude. The telltale symptom users reported was usage limits that appeared to refill and then drain while they weren't actively using the product — a useful concrete sign for anyone checking their own account, and a materially more official and detailed account than the researcher-only coverage this digest carried three days into the campaign's disclosure.

Sources: BleepingComputer, Malwarebytes, Dark Reading
