1. Google Cloud brings agent skills to supercomputing at SC26

This item is about 48 hours old. On 14 November Google Cloud's HPC team published its SC26 announcements, built around reusable agent skills that work with Cluster Toolkit. Its blueprints deploy HPC clusters from declarative YAML. The infrastructure skill has an agent check compute and storage quotas and run quick capacity checks in the region. It then matches the job to a validated blueprint and waits for human approval before running gcluster deploy. Workload skills cover fluid dynamics (OpenFOAM, STAR-CCM+), life sciences (GROMACS, AlphaFold 3) and subsurface simulation (Devito, OPM), and a gke-kueue-debugging skill clears stuck queues. The skills ship through the google/skills and DeepMind Science Skills repositories. Separately, PR #188, merged on 12 November, grew Google's open hpc-agent-antigravity-plugin from 7 to 19 skills with 20 passing test suites. The new skills include chip design (EDA), weather and climate, and quant finance. The approval step before deployment is a good pattern for any skill that spends money.

Sources: Google Cloud blog: What's new in HPC and AI at SC26, scientific-computing-examples PR #188 (19-skill HPC plugin), google-deepmind/science-skills, Cluster Toolkit overview

2. Google's skills library adds Cloud operator setup and teaches its networking skill to load less

Google's public google/skills repository kept up daily commits from 12 to 16 November. On 14 November it added two skills for Google Cloud's operator agent. cloud-operator-setup uses the autocloud MCP server to pick a project and create or find the user's operator agent. cloud-operator-share-context collects context you already have, such as agent instruction files, local memory, existing skills and the repository's GCP docs, and copies only the notes you approve into the agent's memory. A day earlier it added compute-vm-creation for Compute Engine (about 800 lines with templates). On 15 November the networking-observability skill (v1.0.7) was rewritten so the agent loads a single reference guide per task instead of several, with fewer repeated queries. Its rules list shrank from about 18 points to 5. The approve-before-copy step and the one-guide-per-task routing are both easy to reuse in your own skills.

Sources: google/skills commit df4595b: cloud-operator-setup and share-context, Commit 61d3e26: networking-observability streamline, Commit 67c4dbc: compute-vm-creation, google/skills commit history

3. Anthropic's official plugin directory now closes every pull request from outsiders

This item is about 72 hours old. On 13 November Anthropic merged PR #7100 in anthropics/claude-plugins-official, the repository behind Claude's official plugin directory. A workflow now automatically closes every pull request from anyone without write access, whatever it contains. Before, an outside PR could stay open if it only updated a plugin already listed in marketplace.json. That exception and the matching advisory check are gone. Only a maintainer can reopen a closed PR to take it over, and the workflow closes the PR before it comments, so a failed comment can't leave it open. Version-bump PRs from the repository's own automation still go through, and the same day saw bumps for the CrowdStrike, Qodo and BlackRock plugins. If you publish a skills plugin, don't send a pull request to this repository. Ship it from your own marketplace or go through Anthropic's own process.

Sources: claude-plugins-official PR #7100, claude-plugins-official commit history

4. Microsoft Agent Framework rejects skills whose file names differ only by case

This item is about 72 hours old. Microsoft Agent Framework python-1.26.0 shipped on 13 November with PR #10158, merged 10 November, which closes a quiet source of bugs in file-based skills. Skill file lookup ignores letter case, so a skill with both readme.md and README.md could load the wrong file. On Windows, one of the two could also be lost when the skill archive was unpacked. Both the Python and .NET loaders now reject such skills, checking resource and script names separately. They log a warning, skip the skill and keep loading the others. Python also refuses archives that contain both SKILL.md and skill.md. The same release requires Copilot CLI 1.0.85 or later for the GitHub Copilot integration (#10156) and deprecates the old MemoryContextProvider for removal after 31 December 2026 (#10273). If you build skills on macOS or Linux, check that no two file names in a skill differ only in letter case.

Sources: Agent Framework python-1.26.0 release, Agent Framework PR #10158

5. Microsoft's PostgreSQL skills reach 0.3.0 with graph and Oracle-migration skills

On 15 November GitHub's awesome-copilot catalog merged PR #6415, which moves its postgres-skills listing from 0.1.2 to 0.3.0. The listing is pinned to an exact commit in microsoft/postgres-skills. That MIT-licensed plugin works with Claude Code, Copilot CLI and Codex CLI, and contains three skills. postgresql-best-practices points the agent to 23 guides for PostgreSQL and Azure Database for PostgreSQL. pg-graph covers Apache AGE graph workflows, including openCypher queries and retrieval that uses the graph. migrate-oracle-app assesses application code that depends on Oracle and converts it. You can install the full plugin, which includes a local PostgreSQL MCP server, or just the skills with npx skills add microsoft/postgres-skills. The same day awesome-copilot also added an external azure-advisor plugin. It is a useful set of database skills, and the listing shows how catalogs pin a skill pack to an exact commit.

Sources: awesome-copilot PR #6415, microsoft/postgres-skills, awesome-copilot PR #6440 (azure-advisor plugin)
