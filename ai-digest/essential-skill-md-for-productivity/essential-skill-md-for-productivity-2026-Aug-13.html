1. Claude Code makes auto mode the default for Pro, Max, and Team plans starting August 14

Anthropic announced on August 7 that auto mode — letting Claude Code proceed without a per-step approval prompt unless an action is judged "irreversible, destructive, or aimed outside your environment" — becomes the default for new sessions on Pro, Max, and Team plans starting tomorrow, August 14. The company's rationale: in a study of 1,053 paid testers, auto mode caught 89% of harmful actions versus 13.6% for human review, in part because users approve 97% of permission prompts anyway, making manual step-by-step gating mostly theater rather than a real safety layer. The change stays opt-in for now on Claude Enterprise, the Claude API, Claude Platform on AWS, Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry. For anyone assembling a skill library, this raises the stakes on vetting what a skill actually does — skills will now execute end-to-end with even less human-in-the-loop friction by default.

Sources: Claude (official), TechCrunch, The Register

2. Agent Plugins 1.0 goes from paper standard to GA inside VS Code, Copilot CLI, and the Copilot app

The vendor-neutral Agent Plugins 1.0 spec — published August 6 by OpenAI, AWS, Microsoft, Cursor, Vercel and Google, bundling an Agent Skill together with its MCP server config into one distributable package (covered in this digest on Aug 8) — reached its first concrete general-availability milestone on August 12. Support is now live by default in VS Code, GitHub Copilot CLI, the Copilot app, and the Copilot SDK across all Copilot plans, with plugins discoverable through the Awesome Copilot marketplace; existing pre-1.0 Copilot plugins keep working with no forced migration. It's a materially new development on the Aug 8 story: the packaging format has moved from a one-week-old working draft to shipping developer experience faster than most competing agent-extension efforts, and it's the first major client to make Agent Plugins 1.0 the default rather than opt-in.

Sources: GitHub Changelog, VS Code docs

3. GitSkills dataset puts a hard number on SKILL.md sprawl: 3.8M files, 1.9M distinct

A new paper (arXiv 2608.10906, submitted August 11) mines GitHub for every publicly committed SKILL.md file it can find and turns the ecosystem into a citable dataset: 3,797,117 SKILL.md files across 282,200 repositories owned by 195,841 accounts, collapsing to 1,877,981 distinct contents once near-duplicates are hashed out. The authors — Destefanis, Graziotin, Vaccargiu and Ortu — frame skills as an unusual artifact for software-engineering research: natural-language documents a model selects probabilistically at runtime, with no compiler, type checker, or central registry, so they spread by copying folders between repos rather than through a package manager. The paper is slated for the 24th International Conference on Mining Software Repositories (MSR '27) and is positioned to become a reference corpus that skill-security and skill-retrieval papers (SkillCorpus, NVIDIA SkillSpector, and similar work already logged in this digest) can benchmark against.

Sources: arXiv abstract, arXiv full text

4. New runtime-intelligence system tracks where a skill actually breaks — discovered, activated, or silently skipped

A paper posted August 9 (arXiv 2608.08793) tackles a gap most skill tooling ignores: once a skill is loaded, most coding agents give no reliable signal about which lifecycle stage it actually reached — a skill can be discovered but never activated, activated but never given its instructions, or reported "successful" without any independently verified outcome. The author's system, Skill Runtime Intelligence, passively reconstructs those stages across heterogeneous coding-agent harnesses using a "Run Panorama" that separates hard evidence (immutable events) from inference (diagnoses) across a four-level evidence scale, and exports over OTLP/HTTP so it plugs into existing observability stacks. Across 126 test executions spanning six repository profiles, three coding agents, and seven clean-or-fault-injected conditions, every run correlated cleanly back to exactly one source session — a concrete step toward debugging "why didn't my skill fire" instead of guessing from agent chat logs.

Sources: arXiv abstract, arXiv full text

5. Zenity raises $125M Series C, one of the largest checks yet for AI agent/skill governance

Zenity — the AI-agent security and governance vendor whose research uncovered the 1.7M-install "Paperclip" credential-theft campaign hiding in trojanized skills.sh listings (covered in this digest on Aug 9) — closed a $125M Series C on August 3, led by Norwest with new participation from Qumra Capital, Hitachi Ventures, SoftBank Vision Fund 2 and LG Technology Ventures, alongside existing backers including Intel Capital and Vertex Ventures. The round, among the largest yet in the standalone agent-governance category, funds global expansion and platform work for discovering, monitoring and enforcing real-time boundaries on every agent and skill an enterprise runs; Gartner earlier this year called Zenity "the company to beat in AI agent governance." It's as much a market signal as a company story: investors are now pricing "who governs the skill supply chain" as a durable, standalone security category rather than a feature bolted onto existing SaaS-security tools.

Sources: Business Wire, SecurityWeek, Tech Startups
