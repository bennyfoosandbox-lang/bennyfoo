1. Claude Code v2.1.283 adds a skill/agent prompt audit, gateway hint headers, and stricter model allowlists

Anthropic shipped Claude Code v2.1.283 in the early hours of September 26, its second release in two days. The addition most relevant to this digest is a new /doctor prompt-audit subcommand that scans a project's CLAUDE.md files, skills, agents and slash commands for prompting patterns written for older models — surfacing exactly the kind of stale instructions that quietly degrade a skill library as newer Claude generations ship. Alongside that, the release adds an opt-in CLAUDE_CODE_GATEWAY_HINT_HEADERS=1 path that stamps requests with an x-claude-code-prompt-id header so enterprise LLM gateways can group everything serving one user prompt, plus two new managed settings — availableModelsMatch: "exact" and deniedModels — that let admins pin or block specific model versions instead of trusting an allowlist to auto-update. Together the changes read as another step toward unattended, gateway-fronted Claude Code fleets: audit tooling for skill hygiene, plus tighter control over exactly which model those agents are allowed to call.

Sources: GitHub release notes, Claude Code changelog, ccleaks.com

2. Skilder packages enterprise tools into role-scoped skill bundles so agents can't touch what they haven't learned

A new paper, "Progressive Skill Discovery as Access Control for Tool-Using LLM Agents," argues that handing an agent every internal tool up front doesn't just bloat its context — it turns prompt-level governance into what the authors call "probabilistic advice" a confused or compromised agent can simply ignore. Their framework, Skilder, packages capabilities into roles: bundles of skills, tools and instructions plus explicit limits, all delivered through a single MCP server. An agent starts with a minimal role catalog, learns which roles a task actually needs, and only then receives that role's skills and tools; because nothing reaches the agent outside a learned skill, the same server enforces scope deterministically rather than hoping the system prompt is obeyed. For teams treating SKILL.md as a distribution mechanism for internal tooling, it's a concrete architecture for turning "don't touch this" from a polite suggestion into a structural guarantee.

Sources: arXiv:2609.28693, Full text (HTML)

3. SkillGym turns 2,756 human-written skills into training environments to internalize workflows into model weights

"SkillGym: Internalizing Human Skills into LLMs for Real-World Problem Solving" tackles a different failure mode from most skill research: a skill written as external, inference-time instructions never actually becomes part of a model's own competence, so the agent re-reads — and re-pays for — the same workflow every session. SkillGym's skill-to-task pipeline converts existing agent skills into concrete, verifiable tasks, checks outcomes with code-based verifiers, and measures how much a task's success actually depends on the skill through contrastive executions. The authors built and released 2,756 environments across 12 categories and collected 8,364 successful trajectories — averaging 49 tool calls and over 60,000 logged tokens each — from multiple models and harnesses, intended as training data for internalizing skill knowledge rather than just retrieving it at inference time. It's an early but concrete answer to a question this digest keeps circling back to: what happens once a productivity skill library is mature enough to train on, not just prompt with.

Sources: arXiv:2609.27717, Full text (HTML)

4. Microsoft 365 Copilot's Skills in Declarative Agents complete their rollout to general availability

Microsoft's message-center notice MC1476977 confirms that Skills in Declarative Agents — modular packages of instructions, scripts and templates that attach to a Microsoft 365 Copilot agent — are rolling out to general availability, with the rollout beginning mid-September and completing by the end of the month. That closes the loop on the preview this digest covered on September 14: the same packaged-capability model for declarative agents is now shipping broadly instead of being gated to early-access tenants, with Microsoft framing it as the path to more scalable, accurate and maintainable agent experiences without giving up governance or secure execution. For admins standardizing on declarative agents, GA is the signal that Skills have moved from an experimental add-on to something safe to build production workflows around.
